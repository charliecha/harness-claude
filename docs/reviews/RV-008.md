## 2. Security Trigger 触发情况

| 触发类别 | 是否触及 | 说明 |
|---------|---------|------|
| 认证 / 授权 | 否 | — |
| 用户输入处理 | 是 | 用户通过 SAF 选取 URI，`ModelStorage.copyModelFromUri` 处理外部 URI |
| 数据库查询 | 否 | — |
| 文件系统路径 | 是 | URI → 复制到 `filesDir/models/`；`PathValidator` 白名单保护 |
| 外部 API 调用 | 否 | 无网络请求 |
| 加密 / 哈希 | 否 | — |
| 密钥 / 凭证 | 否 | — |

**结论**：触及用户输入处理和文件系统路径，已调用 security-reviewer 审查。

### Security-reviewer 输出摘要

- **URI 处理**：`ModelStorage.copyModelFromUri` 通过 `ContentResolver.openInputStream()` 读取 URI，流式写入，不执行内容；`uri.lastPathSegment` 提取文件名后使用 `substringAfterLast('/')` 防止路径注入，结果通过 `File(dir, name).canonicalPath` 规范化。
- **路径双重验证**：复制目标路径为 `filesDir/models/<filename>`；`LlamaCppModelLoader.load()` 入口处 `PathValidator` 再次校验规范路径，非 `filesDir` 前缀路径返回 `Result.failure`。
- **SAF 权限范围**：`ActivityResultContracts.OpenDocument` 授予的 URI 权限是一次性读权限（API 29+ 无需 `READ_EXTERNAL_STORAGE`），仅用于复制，不持久化 URI 权限。
- **Factory 注入**：`LlamaJni` 是编译时确定的单例，无运行时动态注入风险。
- **`lateinit var vm`**：`MainActivity` 的 `pickModel` 回调在 `onCreate` 之后才可能触发，`vm` 在 `setContent` 中赋值，时序安全。

**Security 结论**：无新增高风险点，现有 `PathValidator` + SAF 权限模型覆盖到位。

## 3. Critical 问题（必须修复）

**Critical 问题数**：0

已扫描维度：
- **资源泄漏**：`ModelStorage` 使用 `use {}` 自动关闭 stream；复制失败时清理部分文件（已有实现）。`loadModelFromUri` 失败路径正确清理 `isCopying`/`isLoading` 状态，无状态泄漏。
- **错误处理**：复制失败（`IOException`、`SecurityException`）和加载失败均通过 `runCatching`/`fold` 传递至 UI `error` 字段，不吞没。
- **并发安全**：`loadModelFromUri` 入口检查 `isCopying || isLoading || modelLoaded`，防止重复调用；与现有 `loadModel` 防护逻辑一致。`_uiState` 为 `MutableStateFlow`，线程安全。
- **内部错误泄漏**：错误消息来自 `Exception.message`，不含 native 指针或内部路径；`Timber` 日志记录文件名而非完整 URI。
- **硬编码密钥**：无。Gatekeeper 扫描通过。

## 4. Warning 问题（建议修复，须说明处理决定）

### W-001 `lateinit var vm` 赋值在 Composable 作用域内，存在潜在时序风险

**文件**：`MainActivity.kt`（`vm = viewModel(factory = vmFactory)` 在 `setContent {}` 内）

`pickModel` 回调访问 `vm`，而 `vm` 在 `setContent` lambda 内赋值。理论上若 `pickModel` 回调在 `setContent` 执行前触发（极端进程恢复场景），会抛 `UninitializedPropertyAccessException`。

**处理决定**：下迭代处理——实践中 `ActivityResultLauncher` 回调只在 `launch()` 之后触发，而 `launch()` 只在 `onLoadModelClick` 中调用，`onLoadModelClick` 只在 UI 渲染完成后可点击，`vm` 必然已赋值。可在后续重构时改为 `by viewModels()` 消除 `lateinit`。

### W-002 SAF MIME 类型 `application/octet-stream` 会展示所有二进制文件，UX 较差

**文件**：`MainActivity.kt`（`pickModel.launch(arrayOf("application/octet-stream"))`）

用户在文件选择器中会看到所有 `.bin`、`.so`、`.zip` 等文件，不易识别 GGUF。

**处理决定**：下迭代处理——GGUF 暂无系统级 MIME 注册；后续可通过 `*/*` + 自定义过滤 UI 改善，但属于 UX 优化，不影响功能正确性。

### W-003 全量行覆盖率 73.3% 低于 80% 目标（分支 66.7% 低于 70%）

同 FR-007 W-003：UI Composable 层（`InferenceScreen`、`MainActivity`）未被单元测试覆盖，Kover 门禁配置排除后已通过。核心 ViewModel 层覆盖充分。

**处理决定**：下迭代处理——UI 测试属独立 FR 范围。

## 5. Info 问题（供参考）

### I-001 `InferenceScreen` 中 `Row` 无垂直居中对齐修饰符

`isCopying`/`isLoading` 状态行使用 `Row(verticalAlignment = Alignment.CenterVertically)`，但外层未设置对齐约束。在不同字体缩放级别下可能出现细微对齐偏差。

### I-002 `InferenceViewModel.Factory` 中使用全限定类名

`kotlinx.coroutines.Dispatchers.IO`、`com.harnessclaude.llm.storage.PathValidator` 等使用全限定名而非 import。风格不统一，但不影响功能。
