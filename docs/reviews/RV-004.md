## 5. Warning 问题

### W-004-1：FR-004-4 AC1 未完整演示 viewModelScope 绑定
**文件**：`android-llm-app/app/src/main/java/com/harnessclaude/llm/MainActivity.kt`  
**说明**：FR-004-4 AC1 要求在示例 `MainActivity` 中演示 viewModelScope 加载并在 scope 取消时自动 release，但当前 `MainActivity` 仅有一个静态 `LoaderScreen()` 组合函数，没有 ViewModel 和实际加载逻辑。  
**影响**：不影响核心功能正确性（`ModelHandle.close()` 已通过单元测试验证幂等释放），但 AC1 的"演示"要求未满足。  
**处理决定**：可在后续 FR（推理 UI）中补全，因为真正的 ViewModel 层属于 UI FR 范畴。本期接受此缺口，但需在下一 FR 的 requirements 中显式列为 dependency。

### W-004-2：smoke_test.sh 未覆盖 Android 层
**文件**：`scripts/smoke_test.sh`  
**说明**：`smoke_test.sh` 只覆盖 Python FastAPI 层。Android 模型加载的冒烟验证需要真机/模拟器，无法在 CI 纯 shell 环境执行。`LlamaCppLoaderInstrumentedTest` 已存在但标注 `@LargeTest`，需要 `connectedAndroidTest` job。  
**影响**：gatekeeper 中 smoke_test.sh PASSED 只验证了 Python 部分。Android 的 JNI 路径仅有本地 build 验证。  
**处理决定**：接受。ADR-004 TODO-6 已标记此已知限制。CI 配置 connectedAndroidTest 属于后续基础设施 FR。

### W-004-3：llama.cpp 为 STUB 模式，未拉取 submodule
**文件**：`android-llm-app/app/src/main/cpp/CMakeLists.txt`，`android-llm-app/third_party/`  
**说明**：当前 CMakeLists.txt 在 `third_party/llama.cpp` 不存在时自动降级为 STUB 模式（返回固定指针 `0xC0FFEE`）。真正的 llama.cpp JNI 路径未在本地构建中验证。  
**影响**：assembleDebug 产出 APK，但装载的 `libllama_jni.so` 是 stub 而非真实 llama.cpp。本地单元测试通过（mock JNI），但 instrumented test 需要真实 `.so`。  
**处理决定**：接受。ADR-004 TODO-5 已标记。STUB 模式是有意设计，避免强制所有开发者拉取 700MB+ submodule。真实集成测试在 CI connectedAndroidTest 中运行。

### W-004-4：`ModelLoadError` 类注释描述指向 Python 专家
**文件**：`.claude/agents/qa-reviewer.md:8`（不在本 PR 范围，仅供参考）  
**说明**：qa-reviewer agent spec 第 8 行声明"你是资深 python 安全与测试专家"，但本次审查对象是 Kotlin/Android。这是 harness 配置问题，不影响审查结果。  
**处理决定**：建议更新 qa-reviewer.md 使其语言无关，记录为 harness 技术债务。

## 6. Info

### I-004-1：`@Synchronized` vs `java.util.concurrent`
**文件**：`ModelHandle.kt:46-54`  
`synchronized(lock)` 配合 `@Volatile var nativePtr` 的双重保护是正确的。在 release() 路径上 `@Synchronized` 足够，并发释放测试（20线程）也验证了 double-free 防护。如后续需要更细粒度控制可考虑 `AtomicLong` 替换，但当前实现符合需求。

### I-004-2：detekt `TooGenericExceptionCaught` 豁免策略
**文件**：`android-llm-app/detekt.yml`，`ModelStorage.kt:52`  
通过 `allowedExceptionNameRegex` 豁免变量名 `t`。这种全局豁免略宽泛——若项目后续新增其他 `catch (t: Throwable)` 而非真正需要全量捕获，可能被误放行。建议改为代码内 `@Suppress("TooGenericExceptionCaught")` 精确豁免。不影响本 FR 功能正确性。

### I-004-3：gatekeeper-checks.sh 子目录 gradlew 发现逻辑
**文件**：`.harness/packs/kotlin/gatekeeper-checks.sh:43-54`  
通过 `find . -maxdepth 2 -name gradlew` 发现子目录 gradlew，是本 FR 引入的新行为。逻辑正确，但若仓库中同时存在多个 Android 子项目，`head -1` 会导致只验证找到的第一个。作为技术债务记录，当前单子项目场景下无影响。
