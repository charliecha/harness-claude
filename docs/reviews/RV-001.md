## 2. Warning（建议修复，须说明处理决定）

### W-001 · httpx.Client 在 with 块外访问 response

- **文件**：`crypto_price_feed/_internal/http.py`，**行 64–66**
- **描述**：`response` 变量在 `with httpx.Client(...) as client:` 块内被创建，但在 `with` 退出（Client 已关闭）之后才被读取：

  ```python
  with httpx.Client(timeout=timeout, headers=headers) as client:
      response = client.get(url, params=params)
  status = response.status_code   # with 块已关闭
  ```

  httpx 的 `Response` 对象会在 Client 关闭后继续持有已完整读取的响应体（httpx 默认同步读取完整响应），因此在实践中不会报错。但这依赖于 httpx 的实现细节；若未来切换为流式响应或更换 HTTP 库，此处将产生资源/逻辑错误。
- **建议**：将 `status`、`response.json()` 的读取移入 `with` 块内，或将 `with` 范围扩大到整个 try 块。
- **处理决定**：目前 httpx 同步模式下完整读取响应，无即时风险；建议在下一迭代中对齐代码结构。

### W-002 · `get_prices` 中 `raw_by_norm` 建立方式冗余且存在边界歧义

- **文件**：`crypto_price_feed/api.py`，**行 78–84**
- **描述**：`normalize_symbols(symbols)` 已完成全量规范化（含异常抛出），随后又对 `symbols` 做第二次逐项 `normalize_symbol` 遍历来建立 `raw_by_norm`。若 `normalize_symbols` 内部过滤了某些符号（理论上不可能，因为它要么成功要么抛出），第二次遍历的 `pragma: no cover` 分支说明此处存在设计上的认知负担。
- **建议**：重构为在 `normalize_symbols` 返回时同时返回原始符号映射，或直接在 `normalize_symbols` 内维护 `raw→norm` 映射，消除重复遍历。
- **处理决定**：功能正确，属于内部实现细节；可在重构迭代中改进。

### W-003 · `_check_freshness` 使用 `abs()` 掩盖时钟偏移方向

- **文件**：`crypto_price_feed/api.py`，**行 28**
- **描述**：`abs((now - quote.source_timestamp).total_seconds())` 会将未来时间戳（`source_timestamp > now`，即上游时钟快于本地时钟）也视为新鲜数据，不会触发 `StaleData`。如果上游时钟漂移严重（如快 120 秒），本地会判为"5 秒新鲜"（60−120 = −60，abs = 60，刚好不超阈值），掩盖潜在问题。
- **建议**：改为单向检查 `(now - quote.source_timestamp).total_seconds() > STALE_THRESHOLD_SECONDS`，同时为过度超前的时间戳增加告警日志。
- **处理决定**：当前规格未明确要求双向检查；建议与产品确认后决定是否修复。

## 3. Info（供参考）

### I-001 · `_build_timeout` 中 `write` 和 `pool` 复用 `HTTP_TOTAL_TIMEOUT`

- **文件**：`crypto_price_feed/_internal/http.py`，**行 27–33**
- **描述**：httpx 的 `write` 超时用于请求体写入，`pool` 超时用于从连接池获取连接。目前均复用 `HTTP_TOTAL_TIMEOUT=2.0s`，对 GET 请求语义正确但参数命名有轻微歧义（`HTTP_TOTAL_TIMEOUT` 实际并非 total timeout）。
- **建议**：考虑在注释或常量名中注明各超时的具体含义；或使用独立常量。

---

### I-002 · `SYMBOL_TO_COIN_ID` 硬编码为模块级常量

- **文件**：`crypto_price_feed/providers/coingecko.py`，**行 24–35**
- **描述**：当前 10 个符号的映射表完全硬编码在源码中。随着支持符号增长，此表将变为维护负担，且无法运行时扩展。
- **建议**：中长期可考虑从配置文件或环境变量加载，或提供注册接口；当前规模下无需急于改动。

---

### I-003 · `BatchResult` 的 `elapsed_ms` 计时区间与 `measure` 的 `elapsed_ms` 重叠

- **文件**：`crypto_price_feed/api.py`，**行 87, 116**
- **描述**：`get_prices` 中同时存在 `measure` context manager（包含整个函数耗时）和手动 `time.perf_counter()` 计时（只计 provider.fetch 之后的部分）。`BatchResult.elapsed_ms` 记录的是从 `start = time.perf_counter()` 到 `return` 之间，而 `measure` 的 `elapsed_ms` 是整个 `with` 块。两者语义不同但名称相同，可能在日志分析时引起混淆。
- **建议**：在文档注释中明确区分两个 `elapsed_ms` 的计时起点；或统一使用 `measure` 提供的计时。
