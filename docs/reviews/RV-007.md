## 2. Security Trigger 触发情况

| 触发类别 | 是否触及 | 说明 |
|---------|---------|------|
| 认证 / 授权 | 否 | 无用户认证相关代码 |
| 用户输入处理 | 是 | `LlamaCppModelLoader.load(path)` 接受外部路径字符串 |
| 数据库查询 | 否 | — |
| 文件系统路径 | 是 | JNI 层直接传入 `path` 给 `llama_model_load_from_file`；`PathValidator` 白名单保护 |
| 外部 API 调用 | 否 | — |
| 加密 / 哈希 | 否 | — |
| 密钥 / 凭证 | 否 | — |

**结论**：触及文件系统路径和用户输入处理，已调用 security-reviewer 审查。

### Security-reviewer 输出摘要

- **路径注入防护**：`PathValidator` 在 Kotlin 层拦截所有非 `filesDir` 前缀路径，返回 `Result.failure`，JNI 层不会收到恶意路径。已通过 `rejects_unsafe_external_storage_path` 测试用例验证。
- **native 堆分配**：`llama_model_load_from_file` 返回 NULL 时，Kotlin 层检查 `ptr == 0L` 并抛 `IllegalStateException`，无裸 NULL 解引用风险。
- **内存释放**：`ModelHandle.close()` 调用 `llama_model_free`（不重复释放，`isReleased` flag 守护），断言已在 `loadModel_afterClose_isReleasedTrue` 测试验证。
- **STUB 哨兵值隔离**：`0xC0FFEE` 哨兵仅在 `#else` 分支（非 LLAMA_CPP_AVAILABLE）注入，生产路径不受影响；集成测试显式断言排除哨兵值。

**Security 结论**：无新增高风险点，现有防护机制覆盖到位。

## 3. Critical 问题（必须修复）

**Critical 问题数**：0

已扫描维度：
- **资源泄漏**：`stagedFixture()` 使用 `use {}` 自动关闭 stream；`ModelHandle.close()` 有 `isReleased` 保护，无 double-free。
- **错误处理**：`runCatching` 包裹 fixture 复制，返回 `null` 而非抛出；`load()` 路径返回 `Result<ModelHandle>`，错误不被吞没。
- **并发安全**：`LlamaCppModelLoader` 在 `Dispatchers.IO` 上运行，无共享可变状态。`isReleased` 为 `@Volatile` 保证可见性（现有实现）。
- **内部错误泄漏**：错误消息不含 native 内存地址；STUB 哨兵值检测在测试层完成，不暴露给用户 UI。
- **硬编码密钥**：无。Gatekeeper 已扫描通过。

## 4. Warning 问题（建议修复，须说明处理决定）

### W-001 `stagedFixture` 返回 `null` 时 `error()` 使测试直接 fail，缺乏诊断信息

**文件**：`LlamaCppLoaderInstrumentedTest.kt`（`loadModel_vocabOnly_returnsValidNativeHandle`）

`stagedFixture(...) ?: error("missing …")` 在 fixture 复制失败时会抛 `IllegalStateException`，JUnit 报告为 Error 而非 Failure，诊断信息（OS 权限、磁盘满）丢失。

**处理决定**：下迭代处理——测试层非核心逻辑，当前在 AVD 上不会触发。可在后续 CI 集成 FR 中改为 `assumeTrue` + 详细 skip message。

**文件**：`InferenceScreen.kt`（3 处）

可提升到文件级 `@file:Suppress`，减少模板代码。

**处理决定**：下迭代处理——Compose 项目惯用做法，不影响正确性。

### W-003 覆盖率低于目标（行 71.2%，分支 65.4%）

整体行覆盖率 71.2% 低于 80% 目标；分支覆盖率 65.4% 低于 70% 目标。注意：Gatekeeper 的 `kover` 覆盖门禁通过，说明 Kover 配置的阈值与全量计算存在差异（Kover 默认排除 UI Composable 和 data class 生成代码）。

## 5. Info 问题（供参考）

### I-001 `ggml-vocab-llama-spm.gguf` 通过 `git add -f` 绕过 `.gitignore`

`.gitignore` 有 `*.gguf` 规则，fixture 通过 `-f` 强制提交。这是有意为之（submodule 内置 fixture，版本锁定），但团队应在 `.gitignore` 中注释或添加例外规则，避免后续开发者混淆。

### I-002 `vocabOnlyLoader()` 辅助方法使用对象委托覆盖单个方法

测试中 `object : LlamaJniBridge by LlamaJni` 的委托模式是 Kotlin 惯用法，正确。但 `vocabOnly = true` 的强制注入逻辑直接硬编码在辅助方法中；若未来需要参数化，可扩展为接受 `vocabOnly` 参数。

### I-003 `InferenceScreenActions` 中 `onLoadModel` 默认值为空 lambda

默认 `{}` 允许调用方省略，但 `InferenceScreen` 调用 `actions.onLoadModel("stub")` 时若确实省略则静默无操作。这是有意的向后兼容设计（STUB 模式下无需 loadModel），需保持文档明确。
