## Warning 问题（建议修复，须说明处理决定）

### W-001：StatsMiddleware 豁免路径需与 RateLimitMiddleware 保持一致

**文件**：`server/middleware.py`，第 31-33 行

修复结论：`StatsMiddleware.dispatch()` 已从单一 `startswith("/stats")` 改为使用 `" /stats", "/health"` 元组检查，与 `_EXEMPT_PREFIXES` 语义一致。**W-001 已关闭。**

### W-002：`_memory_ok` 无缓存机制

**文件**：`server/routes/health.py`，第 15-17 行

每次 `/health` 请求都调用 `psutil.virtual_memory()`，高频轮询场景（如 LB 每秒探测）有微小但可避免的 syscall 开销。

**处理决定**：当前功能正常，首版不预优化。NFR-003-1 要求 P99 ≤ 50ms，`psutil.virtual_memory()` 单次约 1-2ms，不构成风险。后续如需优化可使用 `functools.lru_cache` + 时间戳。

### W-003：`test_is_exempt_from_rate_limit` 依赖隐式的限流器行为

**文件**：`tests/test_health.py`，第 57-61 行

测试通过调用 `/ping`（未注册路由）来耗尽限流器额度。正确但依赖中间件层对所有路径（含 404）计数的实现细节。

**处理决定**：当前可用。后续重构时可更改为显式操作限流器状态或通过 N+1 次循环展示真正的豁免行为。

### W-004：`health()` 缺少返回类型注解

**文件**：`server/routes/health.py`，第 21 行

`async def health()` 无返回类型。项目规则要求所有函数签名使用类型注解。

**处理决定**：建议在下一迭代补充 `-> dict`。

### W-005：服务版本号硬编码

**文件**：`server/routes/health.py`，第 12 行

`_VERSION = "0.1.0"` 与 `pyproject.toml` 的 `version = "0.1.0"` 重复，有漂移风险。

**处理决定**：`pyproject.toml` 的版本也是手工维护的，当前无 CI 自动更新版本号。硬编码与 pyproject.toml 保持一致，同为 "0.1.0"，无即时风险。后续可考虑 `importlib.metadata`。

## Info 问题（供参考）

### I-001：测试 `test_response_has_timestamp_iso8601` 的 `Z` 分支是死代码

Python `datetime.isoformat()` 从不下发 `Z`，而是 `+00:00`。断言兼容了两种格式，实际只有一种会命中。无实际影响。

### I-002：测试的 `_make_app` 未注册 StatsMiddleware

意味着测试不覆盖 `/health` 被 StatsMiddleware 豁免的场景。修复 W-001 后，当前集成测试覆盖率足以保证功能正确性。
