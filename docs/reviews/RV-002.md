## Warning 问题（建议修复，须说明处理决定）

### W-001：`/stats` 端点缺少 `endpoint` 参数的输入验证（ADR-002 §6.2 规定）

**文件**：`server/routes/stats.py`，第 16–41 行

ADR-002 §6.2 明确规定 `endpoint` 参数须拒绝：不以 `/` 开头的字符串、包含 `..`、包含空字节、超过 256 字符的输入。当前代码仅检查 `endpoint is None`，任意字符串均可通过，并被透传到 `StatsQuery.get()` 和 `StatsStore.query()` 中。

**处理建议**：在 `window` 校验之前，对 `endpoint` 参数执行路径格式校验（以 `/` 开头、不含 `..`、不含 `\x00`、长度 ≤ 256）。当前内存存储无真实安全风险，但与 ADR 承诺不符，引入持久化存储时将产生真实风险。

---

### W-002：`server/app.py` 使用已废弃的 `@app.on_event` API

**文件**：`server/app.py`，第 25 和 29 行

`@app.on_event` 在 FastAPI 0.93+ 已标记为 deprecated，推荐使用 `lifespan` context manager。当前版本仍可运行，但在 FastAPI 未来版本中将被移除，届时将导致 `RetentionWorker` 静默不启动。

**处理建议**：迁移至 `@asynccontextmanager` lifespan 模式。优先级低，可记录为技术债务。

---

### W-003：`RetentionWorker` 的 `_run` 方法无异常处理，后台线程会静默退出

**文件**：`crypto_price_feed/stats/_retention.py`，第 26–29 行

若 `purge_before()` 抛出未预期异常，`_run` 将退出循环，后台线程静默终止，7 天保留期清理不再执行（NFR-002-3 失效）。由于线程是 `daemon=True`，进程不会感知到此失败。

**处理建议**：在 `_run` 循环体内加 `try/except Exception` + 日志记录，保证单次清理异常不终止循环。

---

### W-004：并发写入（NFR-002-4）缺乏专项测试

## Info 问题（供参考）

### I-001：`_percentile` 函数的 percentile 索引计算方式不直观

**文件**：`crypto_price_feed/stats/query.py`，第 13–21 行

`statistics.quantiles(data, n=100)` 返回 99 个分位值（n-1 个切割点），索引 `int(p) - 1`（如 p=95 → idx=94）实际对应第 95 个百分位，计算结果正确，但映射关系没有注释说明，对维护者不透明。

**建议**：补充一行注释说明 `statistics.quantiles(n=100)` 返回 99 个值，索引 `p-1` 对应第 `p` 百分位。
