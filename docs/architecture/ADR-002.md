# ADR-002 接口统计功能 - 架构决策

**创建日期**：2026-06-07
**状态**：Proposed
**关联需求**：FR-002
**语言/运行时**：Python 3.11+

---

## 1. 背景与范围

本 ADR 为 FR-002（接口统计功能）定义技术架构，基于 FR-001 / ADR-001 的 `crypto_price_feed` 包扩展，**不另起炉灶**。

核心目标：
- 通过中间件/拦截器自动采集，覆盖全部 FR-001 端点，无需逐一配置（NFR-002-6）。
- 统计三类指标：调用次数（FR-002-1）、响应时间 mean/P95/P99（FR-002-2）、错误率（FR-002-3）。
- 提供独立查询接口，支持时间窗口参数 `1m/5m/1h/24h`（FR-002-4）。
- 写入额外延迟 P99 ≤ 5ms，查询 P99 ≤ 500ms（NFR-002-1/2）。
- 原始样本保留 7 天，聚合摘要保留 30 天（NFR-002-3）。
- 统计查询请求本身不污染被查询端点的计数（FR-002-4 AC4）。

**显式排除**（与 FR-002 第 3 节一致）：实时告警、可视化、用户维度统计、分布式追踪、计费限流、历史数据回填。

## 3. 核心接口定义（Python Protocol 风格）

### 3.1 统计领域模型

```python
# crypto_price_feed/stats/models.py
from dataclasses import dataclass, field
from datetime import datetime

@dataclass(frozen=True, slots=True)
class RequestRecord:
    """单次请求的原始采样记录（写入时产生，保留 7 天）。"""
    endpoint: str          # 如 "/prices/single"
    status_code: int       # HTTP 响应状态码
    duration_ms: float     # 实际耗时，毫秒
    recorded_at: datetime  # UTC，tz-aware

@dataclass(frozen=True, slots=True)
class WindowStats:
    """某端点在某时间窗口内的聚合统计结果。"""
    endpoint: str
    window: str            # "1m" | "5m" | "1h" | "24h"
    total_requests: int
    error_requests: int
    error_rate: float      # 精确到小数点后四位，= error_requests / total_requests
    mean_ms: float
    p95_ms: float
    p99_ms: float
```

### 3.2 StatsStore Protocol

```python
# crypto_price_feed/stats/store.py（Protocol 定义部分）
from typing import Protocol, Sequence
from crypto_price_feed.stats.models import RequestRecord

class StatsStore(Protocol):
    """线程安全的统计存储抽象。

    实现必须：
    - append() 在持有锁时完成，保证 200 并发下计数无误差（NFR-002-4）。
    - query() 返回只读快照（copy），不影响写入侧。
    - purge_before() 由后台定时任务调用，清理过期原始样本。
    """

    def append(self, record: RequestRecord) -> None:
        """追加一条原始采样记录。必须是线程安全操作。"""
        ...

    def query(
        self,
        endpoint: str,
        since: datetime,
    ) -> Sequence[RequestRecord]:
        """返回指定端点、指定时间点之后的所有原始记录快照。"""
        ...

    def purge_before(self, cutoff: datetime) -> int:
        """删除 recorded_at < cutoff 的原始记录，返回删除数量。"""
        ...
```

`InMemoryStatsStore` 是首版唯一实现，内部使用 `collections.deque` + `threading.Lock`。

### 3.3 StatsMiddleware（ASGI 中间件）

```python
# server/middleware.py
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import Response

class StatsMiddleware(BaseHTTPMiddleware):
    """ASGI 中间件，自动拦截所有请求，采集耗时和状态码。

    约束：
    - /stats 路径请求跳过记录（FR-002-4 AC4，避免污染统计数据）。
    - 耗时计量从接收请求到响应发出完成，使用 time.perf_counter()。
    - 采集完成后同步调用 store.append()，总操作须 < 5ms（NFR-002-1）。
    - 任何采集异常必须静默处理，不影响原始请求的响应（fail-open 原则）。
    """

    async def dispatch(self, request: Request, call_next) -> Response:
        ...
```

### 3.4 StatsQuery

```python
# crypto_price_feed/stats/query.py
from crypto_price_feed.stats.models import WindowStats
from crypto_price_feed.stats.store import StatsStore

SUPPORTED_WINDOWS = ("1m", "5m", "1h", "24h")

class StatsQuery:
    """从 StatsStore 聚合计算统计指标。

    约束：
    - P95/P99 基于时间窗口内所有原始样本计算，使用 percentile 插值（FR-002-2 AC3）。
    - 时间窗口内请求数为 0 时，返回 None（FR-002-2 AC4 / FR-002-3 AC4），由路由层翻译为空响应。
    - error_rate 计算仅在 total_requests > 0 时进行，结果 round(..., 4)（FR-002-3 AC2）。
    """

    def __init__(self, store: StatsStore) -> None: ...

    def get(
        self,
        endpoint: str,
        window: str,       # 必须是 SUPPORTED_WINDOWS 之一
    ) -> WindowStats | None:
        """返回聚合统计，无数据时返回 None。"""
        ...
```

### 3.5 HTTP 查询接口契约

```
GET /stats?endpoint=<path>&window=<window>

必填参数：
  endpoint  string   如 /prices/single
  window    string   1m | 5m | 1h | 24h

成功响应 200：
{
  "endpoint": "/prices/single",
  "window": "1h",
  "total_requests": 42,
  "error_requests": 1,
  "error_rate": 0.0238,
  "mean_ms": 123.4,
  "p95_ms": 210.0,
  "p99_ms": 350.0
}

无数据响应 200：
{
  "endpoint": "/prices/single",
  "window": "1h",
  "message": "no data"
}

参数缺失响应 400（FR-002-4 AC3）：
{
  "error": "missing_parameter",
  "missing": "window",
  "allowed_values": ["1m", "5m", "1h", "24h"]
}
```

## 4. 数据流

### 4.1 写入路径（请求 → 统计记录）

```
HTTP 请求（来自外部调用方）
  │
  ▼
StatsMiddleware.dispatch()
  │  1. 若 request.url.path 以 "/stats" 开头 → 跳过采集，直接 call_next（FR-002-4 AC4）
  │  2. t0 = time.perf_counter()
  ▼
call_next(request)          ← 调用 FastAPI 路由（prices.py）
  │  3. 路由内部调用 crypto_price_feed.api.get_price / get_prices
  │  4. 返回 Response（status_code 已确定）
  ▼
StatsMiddleware（续）
  │  5. duration_ms = (time.perf_counter() - t0) * 1000
  │  6. record = RequestRecord(endpoint=path, status_code=..., duration_ms=..., recorded_at=utcnow())
  │  7. store.append(record)   ← 持锁，< 5ms（NFR-002-1）
  │  8. 返回 Response 给调用方
```

### 4.2 查询路径（统计查询 → 聚合结果）

```
GET /stats?endpoint=/prices/single&window=1h
  │
  ▼
stats.py route handler
  │  1. 参数校验：endpoint 和 window 均必填，window 须在 SUPPORTED_WINDOWS 内
  │     缺失时返回 400 + 错误详情（FR-002-4 AC3）
  │  2. StatsQuery.get(endpoint="/prices/single", window="1h")
  ▼
StatsQuery.get()
  │  3. since = utcnow() - window_to_timedelta("1h")
  │  4. records = store.query(endpoint, since)  ← 返回只读快照
  │  5. len(records) == 0 → return None
  │  6. total_requests = len(records)
  │  7. error_requests = sum(1 for r in records if r.status_code >= 400)
  │  8. error_rate = round(error_requests / total_requests, 4)
  │  9. durations = sorted([r.duration_ms for r in records])
  │ 10. mean_ms = sum(durations) / len(durations)
  │ 11. p95_ms = percentile(durations, 95)   ← 线性插值
  │ 12. p99_ms = percentile(durations, 99)
  │ 13. return WindowStats(...)
  ▼
stats.py route handler
  │ 14. None → {"endpoint":..., "window":..., "message": "no data"}
  │ 15. 有数据 → 序列化 WindowStats 为 JSON
  ▼
200 响应
```

### 4.3 过期清理路径（后台任务）

```
_retention.RetentionWorker（后台线程，间隔 5 分钟）
  │  1. cutoff_raw = utcnow() - timedelta(days=7)
  │  2. store.purge_before(cutoff_raw)
  │     （聚合摘要暂无持久化，30 天保留期见 §7 TODO-1）
```

## 5. 技术选型及理由

| 选项 | 决策 | 理由 | 否决的替代方案 |
|------|------|------|----------------|
| **Web 框架** | FastAPI + Starlette | ASGI 原生支持中间件拦截；Pydantic v2 用于请求/响应序列化；与 Python 3.11+ 完美配合。仅本次引入，ADR-001 的库代码不依赖它。 | Flask：WSGI，中间件机制弱；Django：过重 |
| **统计存储** | 内存（`collections.deque` + `threading.Lock`） | 当前规模（10 万次/天 × 7 天 = 70 万条，约 56–100MB）完全可行（NFR-002-5）；零外部依赖；写入操作 O(1)，满足 NFR-002-1（额外延迟 < 5ms）。 | SQLite：引入磁盘 I/O，写入延迟不可控，超出 5ms P99；Redis：需独立部署，运维成本高；PostgreSQL：同上 |
| **P95/P99 计算** | 线性插值 percentile（`statistics` 标准库） | FR-002-2 AC3 明确要求基于实际耗时样本、不使用估算；标准库 `statistics.quantiles` 满足要求，零额外依赖。 | DDSketch/T-Digest：流式近似算法，违反 AC3 "不使用估算"；numpy：引入大依赖，不值当 |
| **中间件自动采集** | ASGI 中间件（`BaseHTTPMiddleware`） | 一次注册覆盖所有路由（NFR-002-6），无需在每个端点手动添加装饰器；路径过滤简单实现 `/stats` 豁免（FR-002-4 AC4）。 | 装饰器：需逐端点配置，违反 NFR-002-6；signal/hook：FastAPI 原生不支持 |
| **并发安全** | `threading.Lock` 细粒度锁 | 200 并发写入时 deque.append 非原子但 GIL 保护追加操作；Lock 用于 query（读快照）和 purge（删除）。满足 NFR-002-4 误差为 0。 | asyncio.Lock：ASGI 环境 store.append 在同步上下文调用，使用 threading.Lock 更合适 |
| **时间窗口实现** | UTC 时间戳截断 + `timedelta` | 无需 cron 或调度框架；每次查询实时计算 `since = now - delta`，天然支持四种窗口；过期清理由后台线程定期执行。 | 预聚合桶（bucket）：实现复杂，且 NFR-002-2 查询 P99 ≤ 500ms 在 10 万样本规模下直接全量扫描已可满足 |
| **ASGI 服务器** | uvicorn（开发/测试）| 标准 ASGI 服务器，与 FastAPI 官方组合；CI 中使用 `TestClient`（httpx）做集成测试，无需真实启动。 | gunicorn：需额外 worker 配置 |

**存储方案决策摘要**：选择内存存储，主要依据：

1. **规模适配**：10 万次/天 × 7 天 × 每条约 100 字节 = 约 70MB，在 NFR-002-5 的 1GB 上限内有充足余量。
2. **延迟要求**：NFR-002-1 要求写入额外延迟 P99 ≤ 5ms，内存操作可保证；磁盘 I/O（SQLite）在并发写时 P99 易超标。
3. **运维简洁**：FR-002 是在现有项目上的扩展，不引入外部依赖符合项目精简原则。
4. **已知局限**：进程重启后统计数据归零，属于已接受的取舍（FR-002 未要求持久化，排除了历史数据回填）。

## 6. 安全边界

### 6.1 统计数据隔离

- `/stats` 端点的请求不计入统计（FR-002-4 AC4），在 `StatsMiddleware` 的**最外层**通过路径前缀匹配实现，早于任何采集逻辑。
- 统计数据只存储端点路径、状态码、耗时、时间戳，**不记录请求参数、响应 body、IP 地址、用户标识**（与 FR-002 排除「用户维度」一致）。

### 6.2 查询接口入参校验

- `endpoint` 参数：仅接受以 `/` 开头的路径字符串，拒绝包含 `..`、空字节或超过 256 字符的输入。
- `window` 参数：严格枚举校验，只接受 `1m/5m/1h/24h`，不接受任意数值，防止非法时间范围导致全量扫描 DoS。
- 缺少参数时返回 400 + 明确错误信息，不暴露内部细节（FR-002-4 AC3）。

### 6.3 并发写入安全

- `store.append()` 持 `threading.Lock` 执行，保证 200 并发下计数零误差（NFR-002-4）。
- `store.query()` 返回 `list` 快照（非 deque 引用），避免遍历期间被其他线程修改。

### 6.4 内存占用上限保护

- `InMemoryStatsStore` 内置软上限检查：当 deque 总大小超过 100 万条时，`append` 触发日志告警（不丢弃数据，仅告警）。
- `RetentionWorker` 保证 7 天 TTL，在正常流量下维持内存在安全范围（NFR-002-5）。

### 6.5 Fail-Open 原则

- `StatsMiddleware` 中任何统计相关异常（`append` 失败、`perf_counter` 异常等）必须被 `try/except` 捕获并静默记录到日志，不向调用方暴露，不影响原始业务响应。

## 7. 已知遗留问题

| 编号 | 问题 | 影响 | 处置 |
|------|------|------|------|
| TODO-1 | 聚合摘要 30 天保留期未实现 | NFR-002-3 要求聚合摘要保留 30 天，但当前架构只保留 7 天原始样本，不落地持久化聚合摘要。 | 首版仅满足 7 天原始样本保留；30 天聚合摘要留待后续 ADR 引入持久化层（SQLite 或文件）实现。 |
| TODO-2 | 进程重启导致统计归零 | 内存存储在服务重启后丢失所有历史数据。 | FR-002 未要求持久化，且排除了历史回填；属已接受取舍。运维层面建议通过进程管理工具（如 systemd）最小化重启次数。 |
| TODO-3 | 高并发下 query 全量扫描性能 | store.query() 对 deque 全量遍历，10 万条时实测应在 50ms 内，满足 NFR-002-2（P99 ≤ 500ms）；但若流量大幅超出预估（>10 万/天）需评估。 | 首版不预优化；若超限，后续可改为按端点分桶的 `dict[str, deque]` 结构。 |
| TODO-4 | P95/P99 在极少样本时的数值稳定性 | 1m 窗口内请求数极少（如 1–3 条）时，P95/P99 与 mean 几乎相同，数值意义有限。 | 不在代码层面特殊处理；结果仍准确（基于实际样本，满足 FR-002-2 AC3）；由调用方根据 total_requests 判断置信度。 |
| TODO-5 | 服务化入口未定义认证机制 | server/ 层无鉴权，/stats 端点对所有调用方开放。 | FR-001 明确排除鉴权（独立关注点），FR-002 同样未定义；生产部署时应通过网络层（反向代理/VPC）限制访问。 |
