# ADR-007 真机 GGUF 加载集成测试 - 架构决策

**创建日期**：2026-06-12
**状态**：Proposed
**关联需求**：FR-007
**语言/运行时**：kotlin + C++17（Android NDK r25b+, arm64-v8a）

---

## 1. 背景与范围

FR-005 完成了 llama.cpp submodule 集成与 `LlamaCppLoaderInstrumentedTest` 框架搭建，但集成测试从未在真机/模拟器上执行过。存在两个阻断问题需要解决：

**问题 1：640B fixture 无法被真实 llama.cpp 加载**
`tinyllama-test.gguf` 含合法 GGUF v3 magic + 13 个 KV 元数据，但 `n_tensors=0`。
真实 `llama_model_load_from_file`（`vocab_only=false`，默认值）在解析时会找不到权重 tensor，导致返回 NULL。
instrumented 测试断言 `nativePtr != 0` 因此必然失败。

**问题 2：llama_jni.cpp 使用新 API 但 ADR-005 文档与实际不符**
`llama_jni.cpp` 已正确使用 `llama_model_load_from_file`（新 API，非 deprecated 的 `llama_load_model_from_file`），代码无需修改，但需确认。

**解决方案**：在 `llama_jni.cpp` 暴露一个 `vocab_only` 参数，或在 `LlamaJniBridge` 接口增加 `loadVocabOnly`，让 instrumented 测试可以用 vocab-only fixture（llama.cpp submodule 自带，无需额外文件）验证真实 JNI 路径。

**排除范围**（同 FR-007）：推理接口真机测试、CI 自动化、STUB 模式移除。

    // vocabOnly=true → params.vocab_only = true, loads without weight tensors
    fun loadModel(path: String, useMmap: Boolean, vocabOnly: Boolean = false): Long

        JNIEnv* env, jobject, jstring jpath, jboolean useMmap, jboolean vocabOnly) {

### 3.5 LlamaCppLoaderInstrumentedTest.kt — vocab fixture 测试

```kotlin
@Test
fun loadModel_vocabOnly_returnsValidNativeHandle() = runBlocking {
    // 使用 submodule 中附带的 vocab fixture（从 assets 复制到 filesDir）
    val fixture = stagedFixture("ggml-vocab-llama-spm.gguf")
        ?: error("missing ggml-vocab-llama-spm.gguf in androidTest/assets")

    // 通过 TestVocabJni 包装调用 vocabOnly=true
    val loader = LlamaCppModelLoader(filesDir = ctx.filesDir)
    val result = loader.loadVocabOnly(fixture.absolutePath)   // 新增扩展/测试辅助

    assertTrue(result.isSuccess)
    val handle = result.getOrThrow()
    assertNotEquals(0L, handle.nativePointer())
    assertNotEquals(0xC0FFEEL, handle.nativePointer())
    handle.close()
    assertTrue(handle.isReleased)
}
```

## 4. 数据流

```
connectedAndroidTest 执行:
  [instrumented test APK]
    → stagedFixture("ggml-vocab-llama-spm.gguf")
        → ctx.assets.open(...) → filesDir/models/ggml-vocab-llama-spm.gguf
    → LlamaCppModelLoader.load(path, vocabOnly=true)
        → PathValidator.requireSafe(path)               ← 路径安全校验
        → LlamaJni.loadModel(path, useMmap=true, vocabOnly=true)   ← JNI
            → check_gguf_magic()                        ← GGUF 头校验
            → llama_backend_init()
            → params.vocab_only = true
            → llama_model_load_from_file(path, params)  ← 真实 llama.cpp
                → 加载 vocab KV（tokenizer），跳过 weight tensors
                → return llama_model*                   ← != NULL, != 0xC0FFEE
        → ModelHandle.create(nativePtr, ...)
    → 断言: nativePtr != 0, != 0xC0FFEE
    → handle.close()
        → LlamaJni.freeModel(ptr)
            → llama_model_free(model)
            → llama_backend_free()
    → 断言: handle.isReleased == true
```

## 5. 技术选型及理由

| 选项 | 决策 | 理由 | 否决的替代方案 |
|------|------|------|----------------|
| Fixture 选择 | 使用 submodule 内置 `ggml-vocab-llama-spm.gguf`（724KB）| 无需外部下载，版本锁定随 submodule，llama.cpp 自身用此文件做 tokenizer 测试，可靠性高 | TinyLlama Q2_K（~550MB，不可入仓）；保留 640B 0-tensor fixture（无法被真实路径加载）；下载 HuggingFace 模型（破坏离线 CI） |
| fixture 放置位置 | 复制到 `androidTest/assets/`（从 submodule 复制一份） | `assetManager` 可直接读取；不依赖 submodule 绝对路径；与现有 `stagedFixture()` 辅助函数兼容 | 从 submodule 路径直接读取（路径在设备上不存在）；用 ExternalStorage（需额外权限）|
| vocabOnly 参数传递 | 在 `LlamaJniBridge.loadModel` 增加 `vocabOnly: Boolean` 默认参数 | 向下兼容（默认 false，生产路径无感知）；让测试可直接使用 public API，不需要 mock | 新增独立 `loadVocabOnly` JNI 方法（接口膨胀）；仅在测试层注入特殊 JNI 实现（隐藏真实路径，失去测试价值） |
| NoOpJni 签名对齐 | `loadModel` 加上 `vocabOnly` 参数，stub 实现忽略该参数 | 保持接口一致性，stub 模式逻辑不变 | 不修改 NoOpJni（编译报错，接口不实现） |

## 6. 安全边界

- **路径校验**：`PathValidator.requireSafe()` 在 Kotlin 层拒绝 `/sdcard/`、`/data/local/tmp` 等危险路径，C++ 层 GGUF magic 校验作为第二道防线。
- **fixture 来源**：`ggml-vocab-llama-spm.gguf` 来自 ggerganov/llama.cpp 官方仓库，随 submodule 入仓，不含训练权重或个人数据。
- **vocab_only 参数**：仅影响 llama.cpp 内部加载策略（跳过 weight tensor），不改变路径校验或内存安全逻辑。
- **日志安全**：logcat 只打印文件路径和 mmap 标志，不打印 native 指针绝对值。
- **无网络权限**：`AndroidManifest.xml` 不含 `INTERNET`，所有操作本地文件。

### B. API 版本说明

当前 submodule（`7242dd967`，gguf-v0.16.0-217）使用：
- `llama_model_load_from_file`（新名，当前 API）—— `llama_jni.cpp` 已正确使用
- `llama_load_model_from_file`（旧名，`DEPRECATED` 标注）—— 不使用
- `llama_model_free`（新名）vs `llama_free_model`（旧名，`DEPRECATED`）—— `llama_jni.cpp` 已正确使用 `llama_model_free`
