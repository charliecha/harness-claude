# ADR-005 集成 llama.cpp Submodule，替换 STUB 模式，实现真实 GGUF 加载

**创建日期**：2026-06-09
**状态**：Proposed
**关联需求**：FR-005
**语言/运行时**：kotlin + C++17（Android NDK r25b+, arm64-v8a）

---

## 1. 背景与范围

FR-004 构建了完整的 GGUF 模型加载 Kotlin 接口与 JNI 桥接层，但 `llama_jni.cpp` 在 `LLAMA_CPP_AVAILABLE` 未定义时以 STUB 模式编译（`loadModel` 返回固定指针 `0xC0FFEE`），无法进行真实的 native 模型加载。

本 ADR 解决：
1. 将 `ggerganov/llama.cpp` 作为 git submodule 集成到 `android-llm-app/third_party/llama.cpp`，锁定稳定 commit
2. `CMakeLists.txt` 在 submodule 存在时启用真实 `add_subdirectory` 路径（现有文件已预留此逻辑，无需大改）
3. 验证 `llama_jni.cpp` 真实路径的正确性（`llama_load_model_from_file` / `llama_free_model`）
4. 新增包含最小 GGUF fixture 的 instrumented 测试，验证真实 JNI 路径

**STUB 降级路径保留**：未初始化 submodule 时仍能 `assembleDebug`，不强制所有开发者拉取 ~500MB submodule。

不涉及：token 生成推理接口、GPU 后端、多 ABI、CI connectedAndroidTest 配置。

### 3.2 CMakeLists.txt — 已预留真实路径


### 3.3 Instrumented 测试断言（扩充）

```kotlin
@LargeTest
@RunWith(AndroidJUnit4::class)
class LlamaCppLoaderInstrumentedTest {

    @Test
    fun loadModel_returnsValidNativeHandle() {
        val assetPath = copyAssetToFiles("tinyllama-test.gguf")
        val loader = LlamaCppModelLoader(filesDir = context.filesDir)
        val result = runBlocking { loader.load(assetPath) }

        assertTrue(result.isSuccess)
        val handle = result.getOrThrow()
        // 真实模式：ptr != 0 且 != 0xC0FFEE
        assertNotEquals(0L, handle.nativePointer())
        assertNotEquals(0xC0FFEEL, handle.nativePointer())
        handle.close()
    }

    @Test
    fun loadModel_afterClose_pointerIsZero() {
        val assetPath = copyAssetToFiles("tinyllama-test.gguf")
        val loader = LlamaCppModelLoader(filesDir = context.filesDir)
        val handle = runBlocking { loader.load(assetPath) }.getOrThrow()
        handle.close()
        assertTrue(handle.isReleased)
    }
}
```

## 4. 数据流

```
[git submodule add] → .gitmodules + android-llm-app/third_party/llama.cpp/

assembleDebug（submodule 已 init）:
  CMake 配置
    → EXISTS third_party/llama.cpp/CMakeLists.txt → TRUE
    → add_subdirectory(llama.cpp) → 编译 libllama.a + libggml.a
    → llama_jni.cpp #if LLAMA_CPP_AVAILABLE=1 → 真实路径
    → link: llama_jni.so ← llama + ggml + log + android

connectedAndroidTest:
  [test APK]
    → copyAssetToFiles("tinyllama-test.gguf") → filesDir/tinyllama-test.gguf
    → LlamaCppModelLoader.load(path)
        → PathValidator.requireSafe(path)         ← AC: no UnsafePath
        → LlamaJni.loadModel(path, useMmap=true)  ← JNI call
            → check_gguf_magic()                  ← AC: valid GGUF
            → llama_load_model_from_file()         ← returns llama_model*
            → return jlong ptr                     ← AC: != 0, != 0xC0FFEE
        → ModelHandle(ptr)
    → handle.close()
        → LlamaJni.freeModel(ptr)
            → llama_free_model()
            → llama_backend_free()
```

## 5. 技术选型及理由

| 选项 | 决策 | 理由 | 否决的替代方案 |
|------|------|------|----------------|
| submodule commit 版本 | `b4530`（2024-09，tag b4530）或其后第一个稳定 tag | 已有大量 Android NDK 验证报告，API 稳定（`llama_load_model_from_file` 签名未变） | HEAD（不稳定，API 随时变化）；b3000 以前（缺少 GGUF v3 支持） |
| submodule 路径 | `android-llm-app/third_party/llama.cpp` | CMakeLists.txt 中已硬编码此相对路径 `../../../../third_party/llama.cpp`，无需修改 CMake | 仓库根 `third_party/llama.cpp`（CMakeLists.txt 路径需全部改写） |
| GGUF fixture 来源 | 手工构造最小合法 GGUF header + 1 个 token embedding tensor（≤ 5 MB） | 不依赖外部 HuggingFace 下载，可版本化入仓；不需完整可推理模型，仅需 `llama_load_model_from_file` 成功返回非 NULL | 使用 TinyLlama 1.1B Q2_K（~550 MB，不可入仓）；从网络下载（破坏离线 CI） |
| llama_backend_init 调用位置 | 每次 `loadModel` 调用前（现有实现） | 简单，多模型场景 llama.cpp 内部幂等处理 | 全局 `JNI_OnLoad` 初始化（需 JNI_OnLoad 管理生命周期，增加复杂性） |
| STUB 降级保留 | 保留（CMake if/else） | 开发者不强制拉取 submodule；CI 无真机时仍能编译 | 完全移除 STUB（强制所有环境有 submodule，破坏现有 CI） |

## 6. 安全边界

- **JNI 指针类型安全**：`freeModel` 接收 `jlong`，通过 `reinterpret_cast<llama_model*>` 还原。Kotlin 侧 `ModelHandle` 用 `@Volatile nativePtr` + `synchronized` 保证 double-free 安全（FR-004 已验证）。
- **路径穿越防御**：`PathValidator.requireSafe()` 在 Kotlin 层执行 canonical path + deny-list 检查，C++ 层不重复做。GGUF magic 校验（4 字节）在 C++ 层作第二道防线，拒绝非 GGUF 内容进入 `llama_load_model_from_file`。
- **asset fixture**：`tinyllama-test.gguf` 是构造的最小 fixture，不含任何训练权重或个人数据；文件经 GGUF magic 头验证后被 llama.cpp 读取，不存在注入面。
- **日志**：logcat 只打印 path 和 mmap 标志位，不打印 native 指针绝对值（已有 `%lld` 格式，可保留）。
- **无网络权限**：`AndroidManifest.xml` 不含 `INTERNET` 权限，submodule 和 fixture 均为本地文件。

## 附录

### A. 风险与降级

| 风险 | 触发条件 | 影响 | 降级策略 |
|------|---------|------|---------|
| llama.cpp b4530 API 与 NDK r25b 不兼容 | `assembleDebug` 出现 C++ 编译错误 | 构建失败 | 切换至更新 tag（如 b5000+）；已在 CMakeLists 设置 `LLAMA_STATIC=OFF`、`LLAMA_BUILD_TESTS=OFF` 减少依赖面 |
| 最小 GGUF fixture 被 llama.cpp 解析失败 | `llama_load_model_from_file` 返回 NULL | instrumented 测试失败 | 换用已知可加载的开源最小 GGUF（如 ggml-vocab-only.gguf） |
| submodule 大小超出 CI 资源 | CI clone 超时 | 构建失败 | `git submodule update --init --depth 1` 浅克隆 |
