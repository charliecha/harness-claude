# ADR-001 加密货币实时报价 - 架构决策

**创建日期**：2026-06-07
**状态**：Accepted
**关联需求**：FR-001
**语言/运行时**：Python 3.11+

---

## 1. 背景与范围

本 ADR 为 FR-001（加密货币实时报价）定义首版实现的技术架构。聚焦：

- 主动 pull 模式的报价查询（单币种 + 批量，上限 20）。
- 多计价货币支持（USD/EUR/CNY，默认 USD）。
- 错误可读、数据新鲜度 ≤ 60s、P99 ≤ 2s。
- 可观测：记录入参、来源时间戳、本地处理耗时。

**显式排除**（与 FR-001 第 3 节一致）：历史价格、预测、交易、鉴权、推送/订阅、多源聚合加权。

---

## 2. 包结构（Python 模块/包）

采用「单包 + 分层」结构，初始仅一个可发布包，遵循「最多 3 个项目」的简洁原则。

```
crypto_price_feed/                    # 顶层包（pip 包名：crypto-price-feed）
├── __init__.py                       # 暴露公共 API：get_price, get_prices, exceptions
├── api.py                            # Facade 层：对外函数式入口（get_price / get_prices）
├── models.py                         # 领域模型：Quote, QuoteResult, BatchResult, FiatCurrency
├── exceptions.py                     # 异常体系：见 §3.4
├── providers/
│   ├── __init__.py
│   ├── base.py                       # PriceProvider Protocol（见 §3.1）
│   └── coingecko.py                  # 首版唯一实现：CoinGecko Public API
├── config.py                         # 配置：超时、上限、默认计价、API Key 读取
├── observability.py                  # 结构化日志 + 计时上下文管理器（见 §3.3）
└── _internal/
    ├── __init__.py
    ├── http.py                       # httpx.Client 封装 + 重试策略
    └── validation.py                 # 入参校验：批量上限 20、币种代码非空等

tests/                                # 与源码平行的测试树（pytest 自动发现）
├── unit/
│   ├── test_api.py
│   ├── test_models.py
│   ├── test_validation.py
│   └── providers/
│       └── test_coingecko.py         # 用 respx mock HTTP
└── contract/
    └── test_provider_contract.py     # PriceProvider Protocol 一致性测试

pyproject.toml                        # 构建 + 依赖 + ruff/mypy/pytest 配置
```

**说明**：
- `_internal/` 前缀下划线，表示「非公共 API，可随时变更」。
- `providers/` 抽象目的不是「未来可能多源」，而是「测试时可注入 fake」，符合 FR-001 排除「多源聚合」的范围。
- 无 CLI、无 HTTP server：本次仅作为库交付（FR-001 未要求服务化）。

## 3. 核心接口定义（Python Protocol 风格）

### 3.1 PriceProvider Protocol

```python
# crypto_price_feed/providers/base.py
from typing import Protocol, Sequence
from crypto_price_feed.models import Quote, FiatCurrency

class PriceProvider(Protocol):
    """单一职责：给定 symbols + fiat，返回 Quote 列表或抛出 ProviderError。

    实现必须：
    - 对网络/上游错误统一映射为 exceptions.py 中的异常类型。
    - 不做入参校验（由上层 validation 负责），但需对上游返回字段做存在性检查。
    - 不缓存、不并发拆分批量请求（首版决策）。
    """

    def fetch(
        self,
        symbols: Sequence[str],
        fiat: FiatCurrency,
    ) -> list[Quote]: ...
```

### 3.2 领域模型

```python
# crypto_price_feed/models.py
from dataclasses import dataclass
from datetime import datetime
from decimal import Decimal
from enum import Enum

class FiatCurrency(str, Enum):
    USD = "USD"
    EUR = "EUR"
    CNY = "CNY"

@dataclass(frozen=True, slots=True)
class Quote:
    """单一币种的成功报价。价格用 Decimal 防止浮点失真。"""
    symbol: str                # 大写，如 "BTC"
    fiat: FiatCurrency
    price: Decimal
    source_timestamp: datetime # 来自上游的报价时间（UTC, tz-aware）

@dataclass(frozen=True, slots=True)
class QuoteError:
    """单一币种的失败结果（用于批量场景的部分失败，FR-001-3 AC4 / FR-001-4 AC3）。"""
    symbol: str                # 用户原始输入（FR-001-4 AC2）
    code: str                  # 错误码，见 §3.4
    message: str               # 人类可读

QuoteResult = Quote | QuoteError  # 单条结果联合类型

@dataclass(frozen=True, slots=True)
class BatchResult:
    """批量查询返回。successes + failures 并集 = 入参 symbols（顺序保持）。"""
    successes: list[Quote]
    failures: list[QuoteError]
    elapsed_ms: int            # 本地处理耗时，NFR-005
```

### 3.3 公共 API（Facade）

```python
# crypto_price_feed/api.py
from collections.abc import Sequence
from crypto_price_feed.models import Quote, BatchResult, FiatCurrency

def get_price(
    symbol: str,
    fiat: FiatCurrency | str = FiatCurrency.USD,
) -> Quote:
    """单币种查询。无效币种 / 不支持的 fiat / 网络失败均以异常返回（见 §3.4）。"""

def get_prices(
    symbols: Sequence[str],
    fiat: FiatCurrency | str = FiatCurrency.USD,
) -> BatchResult:
    """批量查询。symbols 超出 20 抛 BatchSizeExceeded；
    单币种失败进入 BatchResult.failures，不中断其余币种（FR-001-3 AC4）。"""
```

### 3.4 异常体系

```python
# crypto_price_feed/exceptions.py
class PriceFeedError(Exception):
    """所有库异常的基类。带 code 字段，对应 NFR-003。"""
    code: str = "PRICE_FEED_ERROR"

class InvalidSymbol(PriceFeedError):
    code = "INVALID_SYMBOL"        # FR-001-4

class UnsupportedFiat(PriceFeedError):
    code = "UNSUPPORTED_FIAT"      # FR-001-2 AC3

class BatchSizeExceeded(PriceFeedError):
    code = "BATCH_SIZE_EXCEEDED"   # FR-001-3 AC2，message 含上限 20

class StaleData(PriceFeedError):
    code = "STALE_DATA"            # NFR-002：source_timestamp 与 now 差 > 60s

class ProviderError(PriceFeedError):
    code = "PROVIDER_ERROR"        # 上游 5xx / 网络超时 / JSON 解析失败
```

异常对象统一携带 `code`、`message`、`offending_input` 三字段，满足 NFR-003。

### 3.5 可观测性接口

```python
# crypto_price_feed/observability.py
from contextlib import contextmanager

@contextmanager
def measure(operation: str, **fields):
    """结构化日志 + 计时。出入参、source_timestamp、elapsed_ms 由调用方写入 fields。
    首版使用标准库 logging + JSON formatter，无外部依赖。"""
```

## 4. 数据流

### 4.1 单币种查询 `get_price("BTC", "USD")`

```
caller
  │
  ▼
api.get_price
  │  1. validation.normalize_symbol("BTC") → "BTC"
  │  2. validation.parse_fiat("USD")       → FiatCurrency.USD
  │  3. observability.measure("get_price", symbol="BTC", fiat="USD"):
  ▼
providers.coingecko.CoinGeckoProvider.fetch(["BTC"], USD)
  │  4. _internal.http.get(...)        ← httpx.Client，超时 + 1 次重试
  │  5. 解析响应 → Quote(price=Decimal, source_timestamp=...)
  ▼
api.get_price
  │  6. 新鲜度校验：now - source_timestamp > 60s → raise StaleData
  │  7. 返回 Quote
```

### 4.2 批量查询 `get_prices(["BTC","ETH",...], "USD")`

```
caller
  │
  ▼
api.get_prices
  │  1. validation.check_batch_size(len <= 20) → 否则 BatchSizeExceeded
  │  2. validation.normalize_symbols(...)      → 大写、去空白、保序去重
  │  3. validation.parse_fiat(...)
  │  4. observability.measure("get_prices", n=len(symbols), fiat=...):
  ▼
providers.coingecko.CoinGeckoProvider.fetch(symbols, fiat)
  │  5. 单次 HTTP 请求（CoinGecko /simple/price 支持逗号分隔多 id）
  │  6. 响应中缺失的 symbol → 由上层归类为 InvalidSymbol failure
  ▼
api.get_prices
  │  7. 对每个返回的 Quote 做新鲜度校验；过期记为 StaleData failure
  │  8. 组装 BatchResult(successes, failures, elapsed_ms)
  │  9. 返回（不抛异常，除非入参就违规）
```

**关键决策**：批量失败不抛异常（FR-001-3 AC4），只有「入参违规」「整体上游不可达」才抛。

## 5. 技术选型及理由

| 选项 | 决策 | 理由 | 否决的替代方案 |
|------|------|------|----------------|
| **Python 版本** | 3.11+ | `Self` 类型、`StrEnum`、性能提升；3.10 已临近 EOL。 | 3.10：少 1.5 年支持 |
| **HTTP 客户端** | `httpx`（同步模式） | 现代 API、内置超时/重试钩子、与 `respx` 测试 mock 配套。 | `requests`：无 async 升级路径，超时配置较弱；`aiohttp`：库消费者多为同步代码，避免传染 async |
| **数据校验** | 手写 + dataclass（无 pydantic） | 入参很少（symbol/fiat），pydantic 是 50KB+ 依赖的过度工程；FR-001 不暴露 HTTP schema。 | pydantic v2：依赖重 |
| **数值类型** | `decimal.Decimal` | 价格金额必须避免浮点失真；NFR 未规定精度但 BTC 价格量级大、小数位多。 | `float`：精度风险 |
| **日期/时区** | `datetime`（UTC, tz-aware） | 标准库够用；source_timestamp 必须 tz-aware 以正确比较新鲜度。 | `pendulum`：额外依赖 |
| **数据源** | CoinGecko Public API（`/simple/price`） | 公开 Demo 端点可免 Key 起步、批量原生支持、覆盖 USD/EUR/CNY；FR-001 排除多源聚合，单源即可。 | CoinMarketCap：必须 API Key；Binance：fiat 计价支持弱 |
| **重试策略** | 1 次重试，仅对 5xx/网络错误，指数退避 0.5s | NFR-001 要求 P99 ≤ 2s；CoinGecko 超时默认 1.5s，留 0.5s 给重试。 | tenacity：1 次重试不值得引入库 |
| **日志** | `logging` + JSON formatter（自写 ~20 行） | 满足 NFR-005，零依赖。 | structlog：过度工程 |
| **测试** | pytest + respx（httpx mock） | 行业标准；respx 是 httpx 官方推荐 mock。 | unittest：表达力差；vcrpy：录制回放不必要 |
| **构建/打包** | `pyproject.toml` + hatchling | PEP 621 标准；hatchling 是 PyPA 推荐的轻量后端。 | setuptools：legacy；poetry：CI 集成成本高 |
| **代码质量** | ruff（lint + format）+ mypy --strict | ruff 一站式替代 flake8/isort/black；mypy strict 配合 Protocol 强制接口契约。 | black + flake8：重复工具 |

## 6. 安全边界

### 6.1 API Key 处理

首版选择 CoinGecko **Public Demo 端点**，**默认无需 API Key**；但若调用方希望升级到付费端点：

- API Key **仅从环境变量** `COINGECKO_API_KEY` 读取，绝不接受函数参数传入（防止误入日志/调用栈）。
- `config.py` 集中读取一次，封装在 `Config` 对象内；除 `_internal/http.py` 注入 header 外，任何代码路径不得访问该值。
- 异常对象的 `message`、`offending_input`、日志字段中**严禁**包含原始请求 URL 的查询串（CoinGecko 部分付费端点把 key 放 query）。`_internal/http.py` 必须在记录前剥离敏感参数。

### 6.2 入参信任边界

- `symbol` 视为不可信输入：归一化（大写、去空白、长度 ≤ 16）后再拼接 URL；不允许出现 `,`/`/`/`?`/`&` 等 URL 元字符（防止上游 path 注入）。
- `fiat` 必须落在 `FiatCurrency` 枚举内，未匹配即抛 `UnsupportedFiat`。
- 批量上限 20 强制在 `validation.check_batch_size`（FR-001-3 AC1/AC2），防御性也限制单 symbol 字符数与总长度。

### 6.3 网络边界

- 仅访问 `api.coingecko.com` 域名（首版硬编码 base URL，不接受配置覆盖以防 SSRF 类滥用）。
- HTTPS 强制；不接受 `http://`。
- 超时统一 `connect=1s, read=1.5s, total=2s`，对齐 NFR-001。

### 6.4 日志安全

- 日志中可记录：symbol、fiat、elapsed_ms、source_timestamp、HTTP status。
- 日志中**禁止**记录：完整 URL（含 query string）、请求头、API Key、上游返回的完整 body。

## 7. 已知遗留问题

| 编号 | 问题 | 影响 | 处置 |
|------|------|------|------|
| TODO-1 | CoinGecko symbol → coin_id 映射 | CoinGecko `/simple/price` 接受的是 `coin_id`（如 `bitcoin`）而非交易代码（`BTC`）。首版需内置 symbol→id 映射表。 | 首版硬编码常见 ~50 个币种映射；超出范围视为 `InvalidSymbol`。后续 ADR 评估「启动时拉取 /coins/list」缓存方案。 |
| TODO-2 | 新鲜度判定依赖上游时间戳 | CoinGecko `/simple/price` 默认不返回时间戳，需带 `include_last_updated_at=true`。若上游不可用，需 fallback 到本地接收时间。 | 首版以上游 `last_updated_at` 为准；缺失则记 `StaleData` 失败。 |
| TODO-3 | CNY 计价的实际可用性 | 部分上游对 CNY 报价覆盖率低于 USD/EUR。 | 实现阶段需验证；不足时在文档中标注「best-effort」并不修改本 ADR。 |
| TODO-4 | 并发与限流 | CoinGecko Demo 端点限流约 30 req/min，多调用方并发可能触发 429。 | 首版不处理；429 直接映射为 `ProviderError`。后续如需 SDK 级速率控制，单独立 ADR。 |
| TODO-5 | 时钟漂移 | NFR-002 新鲜度判定依赖本地时钟；若部署机时钟偏差 > 60s 会造成误判。 | 不在库内修复；运维责任，文档中提示。 |
| TODO-6 | 同步 vs 异步 | 首版仅同步 API。若未来调用方为 async 框架，需要 `aget_price` 等镜像接口。 | 暂不实现；`httpx` 已为后续平滑迁移留出路径。 |
