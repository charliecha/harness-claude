# ADR-008 真实模型加载：移除 STUB，接入 SAF 文件选择器 - 架构决策

**创建日期**：2026-06-12
**状态**：Accepted
**关联需求**：FR-008
**语言/运行时**：Kotlin / Android (AGP 8.2.2, minSdk 28, targetSdk 35)

---

## 1. 背景与范围

FR-007 已在真机/AVD 上验证 `llama_model_load_from_file` JNI 路径可正确工作。本 ADR 负责将这条路径接入 UI 层：移除 `InferenceViewModel.Factory` 中硬编码的 `stubMode=true` / `NoOpJni`，替换为真实 `LlamaJni`，并通过 Android Storage Access Framework（SAF）允许用户从设备存储选取 GGUF 文件。

变更范围严格限定在 Kotlin/UI 层：不新增 JNI/C++ 代码，不引入新的第三方库，不修改 `LlamaCppModelLoader` / `PathValidator` 核心逻辑。

## 4. 数据流

```
用户点击 "Load Model"
        │
        ▼
InferenceScreen.onLoadModelClick()
        │
        ▼
MainActivity.pickModel.launch(["application/octet-stream"])
        │  系统 SAF 文件选择器
        ▼
ActivityResult: Uri?
        │ 取消 → 无操作
        ▼
InferenceViewModel.loadModelFromUri(context, uri)
        │
        ├─ isCopying = true ──────────────────────► UI: "Copying model…"
        │
        ▼
ModelStorage.copyModelFromUri(context, uri)
        │  8 MiB 流式缓冲复制到 filesDir/models/<filename>
        │  失败 → isCopying=false, error=msg → UI: 错误提示
        ▼
path: String  (filesDir/models/xxx.gguf)
        │
        ├─ isCopying = false, isLoading = true ───► UI: "Loading model…"
        │
        ▼
LlamaCppModelLoader.load(path)
        │  PathValidator 白名单检查
        │  LlamaJni.loadModel(path, useMmap=true, vocabOnly=false)
        │  失败 → isLoading=false, error=msg → UI: 错误提示
        ▼
ModelHandle (nativePtr)
        │
        └─ isLoading=false, modelLoaded=true ─────► UI: 模型已加载，显示 Prompt 输入框
```

## 5. 技术选型及理由

| 选项 | 决策 | 理由 | 否决的替代方案 |
|------|------|------|----------------|
| 文件选取方式 | SAF `ActivityResultContracts.OpenDocument` | Android 官方推荐；无需 `READ_EXTERNAL_STORAGE` 权限（API 29+）；用户可选择任意存储位置 | 手动输入路径：UX 差，安全风险高；`READ_EXTERNAL_STORAGE`：Android 13+ 已废弃 |
| MIME 类型过滤 | `application/octet-stream` | GGUF 无专属 MIME；`application/octet-stream` 展示所有二进制文件，用户可识别 | `*/*`（过宽，选择器显示所有文件）；`model/gguf`（系统未注册，无效） |
| 文件复制位置 | `filesDir/models/` via `ModelStorage` | 已有实现；`PathValidator` 白名单已覆盖此路径；应用私有目录，无需额外权限 | 直接从 URI 加载（不复制）：llama.cpp 需要文件系统路径，SAF URI 不支持直接 mmap |
| `loadModelFromUri` 位置 | `InferenceViewModel` | 保持 UI 层无业务逻辑原则；ViewModel 已持有 `modelLoader` 和状态流 | 在 `MainActivity` 中直接调用：破坏单向数据流，难测试 |
| `onLoadModelClick` 无参设计 | `MainActivity` 持有 launcher，传无参回调给 Screen | Compose 层不应持有 `ActivityResultLauncher`（生命周期不匹配）；MainActivity 是 launcher 的自然宿主 | 在 Composable 中注册 launcher：违反 Compose 生命周期最佳实践 |

## 6. 安全边界

- **入参信任边界**：用户通过 SAF 选取的 `Uri` 不可信。`ModelStorage.copyModelFromUri()` 使用 `ContentResolver.openInputStream()` 读取，流式写入 `filesDir`，不执行内容；`PathValidator` 在 `load()` 入口再次校验目标路径。
- **路径遍历**：`ModelStorage` 使用 `uri.lastPathSegment` 提取文件名，并通过 `File(dir, name).canonicalPath` 规范化，防止 `../` 路径遍历。
- **GGUF 合法性**：`LlamaCppModelLoader` 调用 `LlamaJni.isValidGguf(path)` 校验 magic bytes，非合法文件返回 `Result.failure(InvalidGguf)`，UI 展示错误消息，不进入 JNI 加载流程。
- **日志安全**：`Timber` 日志记录文件名（非 URI 完整字符串，避免泄露用户存储布局）；不记录 nativePtr 值。
- **无网络边界**：本 FR 无网络请求，无需考虑网络安全。

## 附录

### A. 风险与降级

| 风险 | 触发条件 | 影响 | 降级策略 |
|------|---------|------|---------|
| SAF URI 权限过期 | 应用重启后 `ContentResolver` 无法重新打开 URI | 复制失败，`error` 状态展示 | `copyModelFromUri` 返回 `Result.failure`，UI 提示重新选择文件 |
| 磁盘空间不足 | 模型文件 > 可用 `filesDir` 空间 | `ModelStorage.copyModelFromUri` 抛 `IOException` | `runCatching` 捕获，清理部分文件，返回 `Result.failure` |
| OOM 加载超大模型 | 设备 RAM < 模型要求（Q4_K_M 7B ≈ 4GB） | `llama_model_load_from_file` 返回 NULL | `load()` 返回 `Result.failure(LoadFailed)`，UI 显示错误 |
