# ADR-006 端侧 LLM 推理接口 — Token 生成与流式输出

**创建日期**：2026-06-09
**状态**：Proposed
**关联需求**：FR-006
**语言/运行时**：kotlin + C++17（Android NDK r25b+, arm64-v8a）

---

## 1. 背景与范围

FR-005 完成了 llama.cpp submodule 集成，`ModelHandle` 持有有效的 `llama_model*` native 指针。本 ADR 定义从 `ModelHandle` 到流式文本输出的完整推理架构：

- Kotlin 层新增 `inference/` 包，暴露 `InferenceSession`（封装 `llama_context*`）和 `Flow<String>` 生成接口
- JNI 层扩展 `llama_jni.cpp`，新增 context 创建/释放、tokenize、decode、sampler、KV cache 管理函数
- ViewModel 示例补全 FR-004-4 AC1 遗留的 viewModelScope 绑定演示

不涉及：multi-turn 历史格式、GPU 后端、batch size>1、LoRA、speculative decoding。

## 3. 核心接口定义

### 3.1 InferenceParams

```kotlin
data class InferenceParams(
    val maxNewTokens: Int = 128,
    val temperature: Float = 0.8f,
    val topP: Float = 0.9f,
    val seed: Int = -1,
    val nCtx: Int = 512,
    val nBatch: Int = 512,
)
```

### 3.2 InferenceError

```kotlin
sealed class InferenceError(message: String) : Exception(message) {
    class SessionAlreadyReleased(path: String) : InferenceError("session released: $path")
    class HandleReleased : InferenceError("ModelHandle already released before creating session")
    class ContextCreationFailed : InferenceError("llama_init_from_model returned NULL")
    class DecodeFailed(code: Int) : InferenceError("llama_decode failed: code=$code")
    class ConcurrentGeneration : InferenceError("generate() already in progress on this session")
}
```

### 3.3 LlamaJniBridge（扩展）

```kotlin
interface LlamaJniBridge {
    // FR-004（已有）
    fun loadModel(path: String, useMmap: Boolean): Long

    // FR-006（新增）
    fun createContext(modelPtr: Long, nCtx: Int, nBatch: Int): Long

    fun clearKvCache(ctxPtr: Long)

    fun tokenToText(ctxPtr: Long, tokenId: Int): String
    fun isEog(ctxPtr: Long, tokenId: Int): Boolean

```

### 3.4 InferenceSession

```kotlin
class InferenceSession internal constructor(
    private val ctxPtr: Long,
    private val modelPath: String,
    private val nCtx: Int,
    private val jni: LlamaJniBridge,
    private val threadChecker: ThreadChecker,
) : Closeable {

    val contextSize: Int get() = nCtx
    @Volatile private var ctxPtr_: Long = ctxPtr
    val isReleased: Boolean get() = ctxPtr_ == 0L

    private val generating = AtomicBoolean(false)

    fun generate(
        prompt: String,
        params: InferenceParams = InferenceParams(),
    ): Flow<String> = channelFlow {
        check(!threadChecker.isOnMainThread()) { "generate() must not be called on main thread" }
        check(generating.compareAndSet(false, true)) { throw InferenceError.ConcurrentGeneration() }
        try {
            // tokenize prompt
            // decode prefill batch
            // sample loop: decode single token → emit text piece → check EOG / maxTokens / cancel
        } finally {
            generating.set(false)
        }
    }.flowOn(Dispatchers.Default)

    override fun close() { /* synchronized release ctxPtr_ → freeContext */ }
}
```

### 3.5 InferenceViewModel

```kotlin
class InferenceViewModel(
    private val modelHandle: ModelHandle,
    private val sessionFactory: InferenceSessionFactory,
) : ViewModel() {

    data class UiState(
        val generatedText: String = "",
        val isGenerating: Boolean = false,
        val error: String? = null,
    )

    private val _uiState = MutableStateFlow(UiState())
    val uiState: StateFlow<UiState> = _uiState.asStateFlow()

    fun generate(prompt: String) {
        viewModelScope.launch(Dispatchers.Default) {
            val session = sessionFactory.create(modelHandle, InferenceParams())
            session.use {
                it.generate(prompt).collect { piece ->
                    _uiState.update { s -> s.copy(generatedText = s.generatedText + piece) }
                }
            }
        }
    }
}
```

## 4. 数据流

```
[用户输入 prompt]
    ↓
InferenceViewModel.generate(prompt)
    ↓  viewModelScope.launch(Dispatchers.Default)
InferenceSessionFactory.create(modelHandle, params)
    ↓  JNI: llama_init_from_model(modelPtr, ctx_params)
InferenceSession(ctxPtr)
    ↓
InferenceSession.generate(prompt, params)  → channelFlow
    │
    ├─ JNI: tokenize(ctxPtr, prompt, addBos=true) → IntArray
    ├─ JNI: decode(ctxPtr, promptTokens)           → prefill
    │
    └─ LOOP (i < maxNewTokens && !isClosedForSend):
        ├─ JNI: sampleNext(ctxPtr, temp, topP, seed) → tokenId
        ├─ JNI: isEog(ctxPtr, tokenId)               → if true → break
        ├─ JNI: tokenToText(ctxPtr, tokenId)          → piece: String
        ├─ send(piece)                                → Flow<String> emit
        └─ JNI: decode(ctxPtr, [tokenId])             → autoregressive step

    ↓  Flow complete / cancel
InferenceSession.close()
    ↓  JNI: freeContext(ctxPtr)

[UI: collect Flow → _uiState.update → Compose recompose]
```

## 5. 技术选型及理由

| 选项 | 决策 | 理由 | 否决的替代方案 |
|------|------|------|----------------|
| Flow 实现方式 | `channelFlow { }` + `flowOn(Dispatchers.Default)` | `channelFlow` 支持在协程中 `send`，`flowOn` 将 C++ 阻塞推理隔离到 Default dispatcher；cancel 信号通过 `isClosedForSend` 传递 | `callbackFlow`（需要额外 callback 机制）；`flow { emit }` + `buffer`（不支持 C++ 侧取消检测） |
| sampler 策略 | `sampleNext` 封装 greedy + top-p + temperature chain（C++ 侧） | b4999 推荐 `llama_sampler_chain`；chain 在 C++ 侧管理比 Kotlin 手动处理 logits 更安全 | 在 Kotlin 侧读取 logits float[] 自行采样（跨 JNI 传递大数组性能差） |
| KV cache 策略 | AC5：同一 session 每次 generate 不清空 KV cache | 支持 multi-turn 追加，符合 FR-006-3 AC5 | 每次 generate 重建 context（开销大，破坏对话连续性） |
| context 生命周期 | 一个 `InferenceSession` 对应一个 `llama_context*`，session close 时释放 | 明确所有权，与 `ModelHandle` 的 `Closeable` 模式对称 | 全局单例 context（并发保护复杂，不支持多 session） |
| 并发保护 | `AtomicBoolean generating` 守卫，第二次调用抛 `ConcurrentGeneration` | 最简单且足够；llama.cpp 不支持同一 context 并发 decode | Mutex/Semaphore（更复杂，无必要） |
| ViewModel 注入 | 构造函数注入 `ModelHandle` + `InferenceSessionFactory` | 可测试性；避免在 ViewModel 内部直接 load 模型 | Hilt（本期 DI 框架未引入，首版手工注入即可） |

## 6. 安全边界

- **JNI 指针传递**：`ctxPtr`（`llama_context*`）通过 `jlong` 传递，`@Volatile + synchronized` 防止 double-free，与 `ModelHandle` 模式一致。
- **主线程防护**：`generate()` 开头 `check(!threadChecker.isOnMainThread())`，阻止主线程调用 C++ 阻塞循环。
- **prompt 内容**：`tokenize` 接受任意 UTF-8 字符串，llama.cpp 内部处理，不执行 prompt；无注入风险。
- **日志**：不打印 prompt 内容到 logcat（隐私保护），只打印 token count 和耗时。
- **native 内存**：KV cache 在 `llama_context` 内部分配（native heap），不跨越 JVM 堆；session close 时 `freeContext` 释放。
- **错误传播**：C++ `llama_decode` 返回非零时映射为 `InferenceError.DecodeFailed`，不 crash；不暴露 C++ 内部错误码细节给 UI。

## 附录

### A. 风险与降级

| 风险 | 触发条件 | 影响 | 降级策略 |
|------|---------|------|---------|
| `llama_decode` 在 header-only GGUF 上 crash | instrumented 测试用当前 fixture | crash | instrumented 测试 mock JNI bridge，不调真实 decode |
| `llama_sampler_chain` API 在 b4999 行为与文档不符 | 采样结果异常 | token 生成质量差 | 降级为 greedy（`llama_sampler_init_greedy`） |
| `channelFlow` cancel 时 C++ 侧仍在阻塞 `llama_decode` | Flow job cancel 后 native 线程泄漏 | 内存泄漏 | 设置 `llama_context_params.abort_callback`，检查协程 `isActive` |
