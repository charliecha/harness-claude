# ADR-003 API 健康检查 - 架构决策

**创建日期**：2026-06-09
**状态**：Accepted
**关联需求**：FR-003
**语言/运行时**：Python 3.11+

---

## 1. 背景与范围

本 ADR 为 FR-003（API 健康检查）定义实现架构。FR-003 在 `server/` 层新增端点，不修改 `crypto_price_feed` 核心库。

核心目标：
- 暴露 `GET /health` 端点，返回状态、版本号、时间戳（FR-003-1）。
- 可选返回 `checks.memory` 依赖状态（FR-003-2）。
- `/health` 不受限流（FR-003-2）、不计入统计（FR-003-3）。
- 响应时间 P99 ≤ 50ms（NFR-003-1）。

**显式排除**（与 FR-003 第 3 节一致）：鉴权、外部依赖探测、告警、liveness/readiness 分离。

## 3. 核心接口定义

### 3.1 GET /health 响应契约

```python
@router.get("/health")
async def health() -> dict:
    return {
        "status": "ok",
        "version": "0.1.0",
        "timestamp": datetime.now(tz=UTC).isoformat(),
        "checks": {
            "memory": "healthy",       # 或 "degraded"
        },
    }
```

### 3.2 内存探测

```python
# server/health.py
import psutil

def _memory_ok() -> bool:
    """Return True if memory usage is below 90%."""
    return psutil.virtual_memory().percent < 90
```

### 3.3 豁免注册

`_EXEMPT_PREFIXES` 增加 `"/health"` 后，RateLimitMiddleware 和 StatsMiddleware 都会跳过该路径，满足 NFR-003-2 和 FR-003-1 AC5。

## 4. 数据流

```
GET /health
  │
  ▼
RateLimitMiddleware.dispatch()
  │  path.startswith("/health") → True → 跳过限流，直接 call_next
  ▼
StatsMiddleware.dispatch()
  │  path.startswith("/health") → True → 跳过统计，直接 call_next
  ▼
health()
  │  1. memory_ok = _memory_ok()
  │  2. checks["memory"] = "healthy" if memory_ok else "degraded"
  │  3. 返回
  ↓
JSON Response
```

## 5. 技术选型及理由

| 选项 | 决策 | 理由 | 否决的替代方案 |
|------|------|------|----------------|
| **版本号来源** | 硬编码 `app.version` 字符串 | 当前无 package 发布流程，无 `__version__` 或 git tag。硬编码为 "0.1.0"，与技术选型保持一致（首版未定义版本化）。`app.version` 实为 FastAPI 的 `version` 参数（支持 `get_registered_routes` 访问）。 | `importlib.metadata`：包项目 `crypto-price-feed` 可能未正确注册版本；`git describe`：运行时开销 |
| **内存检测** | `psutil.virtual_memory().percent` | Python 标准库无内存检测能力；`psutil` 是跨平台内存/CPU 检测的事实标准，轻量且成熟。 | 解析 `/proc/meminfo`：不可移植（macOS/Win 失效） |
| **健康状态模型** | 扁平 JSON（不会嵌套超过必要的粒度） | 当前版本仅一个检查项，扁平结构足够。保持与 `/stats` 的风格一致。 | JSON:API 格式过度工程；HAL：不必要 |
| **限流豁免** | `_EXEMPT_PREFIXES` 元组增加成员 | 零额外复杂度，与现有 `/docs`、`/stats` 豁免机制一致。 | 新建独立的豁免机制增加了不必要的实现路径 |

## 6. 安全边界

### 6.1 信息泄漏最小化

- `/health` 版本号与 FastAPI app 的 `version` 参数一致，首版为固定 "0.1.0"。
- 内存使用百分比是常见的健康检查指标，不构成敏感信息。

### 6.2 请求验证

- `GET /health` 不接受任何查询参数或 body，无注入向量。

### 6.3 依赖包

- `psutil` 是成熟的系统工具库，CVEs 极少。如果未来团队决定移除可选依赖，可将 `_memory_ok` 包裹在 `try/except ImportError` 中，在 import 失败时返回 `"unknown"`，但首版将 `psutil` 列为基础依赖。
