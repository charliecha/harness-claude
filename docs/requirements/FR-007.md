# FR-007 真机 GGUF 加载集成测试

**创建日期**：2026-06-11
**状态**：Active
**Feature**：fr-007-real-device-gguf-integration-test

---

## 1. 业务上下文

- **谁会用**：Android LLM App 开发者（本地真机验证）、CI 接入后的自动化质量门禁。
- **解决什么问题**：FR-005 虽然完成了 llama.cpp submodule 集成与 instrumented 测试框架搭建，但实际的 `connectedAndroidTest`（真机/模拟器上运行 JNI 路径）从未执行过。当前 `LlamaCppLoaderInstrumentedTest` 仍依赖 STUB 模式（`InferenceViewModel.Factory` 注入 `NoOpJni`，`stubMode=true`），真实 JNI 路径 `llama_load_model_from_file` 尚未在设备上验证过。
- **价值**：跑通真机集成测试后，可以确认 `libllama_jni.so`（真实模式）在 arm64-v8a 设备上能正确加载合法 GGUF fixture，返回有效 native 指针，并在 `close()` 后正常释放内存。这是推理接口（FR-006 已完成 Kotlin 层，C++ 层仍为 STUB）最后的真实路径验证。

---

## 2. 功能需求

### FR-007-1 LlamaCppLoaderInstrumentedTest 在真机上通过

`LlamaCppLoaderInstrumentedTest`（已存在于 `androidTest/`）在连接真机或模拟器时，通过 `connectedAndroidTest` 执行，所有三个测试用例均绿。

**验收标准**：
- AC1：`./gradlew connectedAndroidTest` 执行完毕，`LlamaCppLoaderInstrumentedTest` 中 3 个测试全部 PASS（`loadModel_returnsValidNativeHandle`、`loadModel_afterClose_isReleasedTrue`、`rejects_unsafe_external_storage_path`）。
- AC2：`loadModel_returnsValidNativeHandle` 断言 `nativePtr != 0` 且 `nativePtr != 0xC0FFEEL`，即确认真实 JNI 路径被调用，非 STUB 路径。
- AC3：设备 logcat 中出现 `ModelLoader` tag，记录 `loaded path=...` 行，不出现 `SIGSEGV` 或 `double-free`。

### FR-007-2 GGUF fixture 确认为合法可加载文件

`androidTest/assets/tinyllama-test.gguf`（640 字节最小 fixture）能被真实 `llama_load_model_from_file` 解析并返回非 NULL 指针。

**验收标准**：
- AC1：`tinyllama-test.gguf` 包含合法 GGUF v3 magic（`GGUF\x03\x00\x00\x00`）和最小元数据，llama.cpp 不返回解析错误。
- AC2：若当前 fixture 无法被真实 llama.cpp 加载（返回 NULL），则替换为已知可加载的最小合法 GGUF（如 `ggml-vocab-only.gguf` 或 TinyLlama Q2_K 截断版），并更新 fixture 文件。

### FR-007-3 STUB 模式回归测试不受影响

修改测试/fixture 后，`./gradlew test`（单元测试，含 STUB 模式 ViewModel 测试）仍全部 PASS。

**验收标准**：
- AC1：`./gradlew test` 在修改后全部绿，覆盖率 ≥ 80%。
- AC2：`InferenceViewModel.Factory` 的 `stubMode=true` 注入不被改动，STUB 路径对 ViewModel 层测试无影响。

## 4. 排除范围

- **推理 token 生成的真机测试**：本 FR 只验证 `loadModel` / `freeModel` JNI 路径，不运行 `eval` / `sampleNext`。
- **CI connectedAndroidTest 自动化接入**：配置 Firebase Test Lab 或 GitHub Actions 模拟器属于独立基础设施 FR。
- **多真机/多 API 级别矩阵**：只需在一台设备上通过。
- **完整可推理模型（> 100MB）**：fixture 仍使用最小文件，不下载完整 TinyLlama 权重。
- **STUB 模式移除**：`InferenceViewModel.Factory` 的 `stubMode=true` 不在本 FR 改动范围。

## 5. 依赖与影响范围

**上游依赖**（本功能需要什么）：
- `android-llm-app/third_party/llama.cpp`：已初始化的 git submodule（FR-005 完成）
- `app/src/androidTest/assets/tinyllama-test.gguf`：最小 GGUF fixture（FR-005 已创建，需验证可被真实 llama.cpp 加载）
- `LlamaCppLoaderInstrumentedTest.kt`：已存在的 instrumented 测试（FR-005 已创建）
- 连接的 Android 设备或 AVD（arm64-v8a，API 28+）

**下游影响**（本功能改动会影响什么）：
- `androidTest/assets/tinyllama-test.gguf`：可能需要替换为更完整的 GGUF fixture（若当前 640B 无法被真实 llama.cpp 解析）
- `LlamaCppLoaderInstrumentedTest.kt`：可能需要调整测试辅助逻辑（不改核心断言）
- `docs/requirements/INDEX.md`、`docs/architecture/INDEX.md`：新增 FR-007 / ADR-007 条目

**变更范围**：验证/修复现有测试 + 可能更新 GGUF fixture，不新增 Kotlin 业务逻辑。
