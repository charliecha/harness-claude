# FR-004 Android LLM 推理助手 - 项目初始化与 GGUF 模型加载

**创建日期**：2026-06-09
**状态**：Active
**Feature**：fr-004-gguf-model-loading

---

## 1. 业务上下文

- **谁会用**：希望在 Android 设备本地运行开源 LLM（Llama 3、Qwen、Phi 等 GGUF 量化模型）的开发者与终端用户。
- **解决什么问题**：当前 harness-claude 仓库尚无 Android 端能力，团队需要一个能加载本地 GGUF 模型、可被后续推理 / UI / 工具调用 FR 复用的基础设施。模型加载是 LLM 应用的"地基"——一切推理、UI、对话历史都依赖一个可用的 `ModelHandle`。
- **价值**：交付后团队可在 Android 端拿到 `ModelHandle`，作为后续 FR（推理接口、Compose UI、对话存储）的输入；终端用户可在断网环境下使用本地 LLM。

## 2. 功能需求

### FR-004-1 Android 项目脚手架

新建 `android-llm-app/` 子目录，包含可独立 Gradle 构建的 Android 应用模块。

**验收标准**：
- AC1：`android-llm-app/` 下执行 `./gradlew assembleDebug` 成功产出 `app-debug.apk`
- AC2：项目使用 Kotlin DSL（`build.gradle.kts`），AGP ≥ 8.2，Kotlin ≥ 1.9.22，targetSdk = 34，minSdk = 28
- AC3：包含一个空的 `MainActivity`（Jetpack Compose），仅显示"Model Loader Ready"占位文本，能在模拟器启动
- AC4：CMake + NDK 集成 llama.cpp 子模块，编译产物为 arm64-v8a 一个 ABI 的 `libllama_jni.so`

### FR-004-2 GGUF 模型加载接口

定义 `ModelLoader` 抽象，能从指定文件路径加载 GGUF 模型并返回 `ModelHandle`。

**验收标准**：
- AC1：暴露挂起函数 `suspend fun ModelLoader.load(path: String): Result<ModelHandle>`，必须在 `Dispatchers.IO` 上执行
- AC2：`load()` 在主线程调用会抛 `IllegalStateException`（防御性检查）
- AC3：`ModelHandle` 实现 `Closeable`；`release()` 调用后再次访问 native pointer 抛 `IllegalStateException`
- AC4：相同 `ModelHandle` 上 `release()` 多次调用是幂等的（仅第一次释放 native 资源）
- AC5：传入不存在 / 不可读 / 非 GGUF 文件，返回 `Result.failure` 且 native 端不泄漏内存
- AC6：使用 `mmap` 加载（即 `llama_model_params.use_mmap = true`），不全量读入 JVM 堆

### FR-004-3 模型来源策略

模型文件来源支持两种路径：应用私有存储（`context.filesDir`）与外部存储（用户通过 SAF 选择的 `Uri` 复制后的本地路径）。

**验收标准**：
- AC1：提供工具函数 `copyModelFromUri(context, uri): String`，返回拷贝到 `filesDir/models/<filename>` 后的绝对路径
- AC2：拷贝过程使用流式 IO，不一次性读入内存
- AC3：拷贝失败（磁盘满 / 权限不足 / Uri 失效）返回 `Result.failure`，已写入的部分文件被删除（无残留）

### FR-004-4 资源生命周期

`ModelHandle` 与持有它的 ViewModel / 协程作用域绑定，scope 取消时自动 `release()`。

**验收标准**：
- AC1：在示例 `MainActivity` 中演示：用 `viewModelScope` 启动加载，scope 取消时 native handle 自动释放（用日志验证 `release()` 被调用一次）
- AC2：不允许 `GlobalScope.launch` 加载模型（gatekeeper 静态扫描会拦截）

## 3. 非功能需求

| 编号 | 类别 | 描述 |
|------|------|------|
| NFR-004-1 | 性能 | 加载 Q4_K_M 量化的 1B 模型（≈ 700MB）的耗时 ≤ 3 秒（Pixel 6 / SD888 级别） |
| NFR-004-2 | 内存 | 加载 1B 模型后 JVM 堆增长 ≤ 50MB（绝大部分内存通过 mmap，由 kernel 管理） |
| NFR-004-3 | 兼容性 | 仅支持 arm64-v8a + Android 9 (API 28) 及以上 |
| NFR-004-4 | 可观测性 | 加载耗时、模型路径、ABI、native lib 版本通过结构化日志（Timber）输出 |
| NFR-004-5 | 测试覆盖 | 单元测试覆盖率 ≥ 80%；JNI 边界至少有 1 个 instrumented test 验证 native 路径 |
| NFR-004-6 | 安全 | 模型路径必须在 `context.filesDir` 下；拒绝 `/sdcard/`、`/data/local/tmp` 等危险路径（防 path traversal） |

## 4. 排除范围

明确不属于本次交付内容：

- **推理 API**：`generate(prompt) -> token stream` 由后续 FR 实现
- **对话 UI**：Compose 聊天界面是独立 FR
- **模型下载 / Hub 集成**：本 FR 假设模型已存在于本地，不实现从 HF / 自建 server 拉取
- **多模型并存 / 切换**：一次只持有一个 `ModelHandle`
- **GPU 加速**：仅 CPU 推理路径（OpenCL / Vulkan backend 后续 FR）
- **Tokenizer 自定义**：用 llama.cpp 内置 tokenizer
- **量化策略选择**：调用方负责选 Q4_K_M / Q5_K_M 等
- **多 ABI 支持**：armv7、x86_64 不在本期范围
- **KV cache、context window 参数调优**
