# FR-008 真实模型加载：移除 STUB，接入 SAF 文件选择器

**创建日期**：2026-06-12
**状态**：Active
**Feature**：fr-008-real-model-loading

---

## 1. 业务上下文

- **谁会用**：Android 设备用户，通过 App UI 在设备上运行本地 LLM 推理。
- **解决什么问题**：FR-007 已验证真实 JNI 路径（`llama_model_load_from_file`）可在真机/AVD 上正确工作，但 `InferenceViewModel.Factory` 仍硬编码 `jni = NoOpJni`、`stubMode = true`。用户点击"Load Model"按钮无法加载真实 GGUF 文件，推理输出始终为空（NoOp）。
- **价值**：交付后用户可通过系统文件选择器选取设备上的 GGUF 模型文件，App 将模型复制到安全目录后真实加载，从而在设备本地运行 LLM 推理，不依赖网络或云端。

---

## 2. 功能需求

### FR-008-1 移除 ViewModel Factory 的 STUB 注入

`InferenceViewModel.Factory` 改为注入真实 `LlamaJni`（`stubMode = false`），使 UI 层通过真实 JNI 路径加载模型。

**验收标准**：
- AC1：`InferenceViewModel.Factory.create()` 中 `jni = LlamaJni`、`stubMode = false`。
- AC2：`./gradlew test` 中 STUB 相关单元测试（`LlamaCppModelLoaderTest`、`InferenceViewModelTest`）仍全部通过（不依赖 `stubMode=true`）。
- AC3：`NoOpJni` 保留在代码库中，可被测试或未来隔离模式复用，但不再是 Factory 的默认注入。

### FR-008-2 SAF 文件选择器接入

`MainActivity` 注册 `ActivityResultContracts.OpenDocument`，允许用户从设备存储选取 GGUF 文件；选取后通过 `ModelStorage.copyModelFromUri()` 复制到 `filesDir/models/`，再调用 `vm.loadModel(path)`。

**验收标准**：
- AC1：用户点击"Load Model"按钮，系统文件选择器弹出，过滤 `application/octet-stream`（GGUF 无专属 MIME，使用通用二进制类型）。
- AC2：用户选择文件后，App 显示加载进度（`isLoading = true`），加载成功后按钮消失，`modelLoaded = true`。
- AC3：用户取消文件选择器，UI 不改变（无错误状态）。
- AC4：若所选文件非合法 GGUF（`isValidGguf` 返回 false），UI 显示错误消息，不崩溃。

### FR-008-3 InferenceUiState 新增模型路径与文件复制进度

加载流程需要展示两阶段状态：文件复制中（从 URI 到 filesDir）和模型加载中（JNI 初始化）。

**验收标准**：
- AC1：`InferenceUiState` 新增 `isCopying: Boolean`，文件复制阶段 `isCopying = true`，加载阶段 `isLoading = true`。
- AC2：UI 在 `isCopying` 时显示"Copying model…"，在 `isLoading` 时显示"Loading model…"，两者互斥显示。
- AC3：`InferenceViewModel` 新增 `loadModelFromUri(context: Context, uri: Uri)` 方法，封装复制 + 加载两阶段流程。

## 3. 非功能需求

| 编号 | 类别 | 描述 |
|------|------|------|
| NFR-008-1 | 文件复制性能 | `copyModelFromUri` 使用 8 MiB 缓冲流式复制，不将整个文件加载进内存 |
| NFR-008-2 | 路径安全 | 复制目标路径须通过 `PathValidator` 白名单检查（`filesDir/models/`），禁止写入外部存储 |
| NFR-008-3 | 错误不崩溃 | 非合法 GGUF、文件读取权限拒绝、磁盘满等情况均通过 `Result.failure` 向 UI 传递，不抛出未捕获异常 |
| NFR-008-4 | 内存安全 | 加载失败时 `ModelHandle` 不泄漏（`load()` 返回 `failure` 前已调用 `freeModel`） |
| NFR-008-5 | 构建兼容 | 修改后 Gatekeeper 10/10 通过（ktlint、detekt、assembleDebug、testDebugUnitTest、kover） |

## 4. 排除范围

- **推理 token 生成的真机完整测试**：本 FR 只验证 `loadModel` UI 流程，不运行 `generate()` 真机测试。
- **模型列表管理**：已加载模型的列表页、删除、切换属于独立 FR。
- **下载模型功能**：从网络下载 GGUF 属于独立 FR，本 FR 只支持从本地存储选取。
- **多模型并发加载**：`InferenceViewModel` 仍只持有单个 `modelHandle`。
- **C++ 推理层（eval / sampleNext）真机验证**：`InferenceSessionFactory` 已注入 `LlamaJni`，但推理流程的真机集成测试属于独立 FR。
- **权限请求 UI**：SAF `OpenDocument` 不需要 `READ_EXTERNAL_STORAGE` 权限（Android 10+），无需额外权限对话框。

## 5. 依赖与影响范围

**上游依赖**：
- `LlamaJni`：已实现的真实 JNI 单例（FR-005 完成）
- `ModelStorage.copyModelFromUri()`：已实现的 SAF 文件复制基础设施（FR-004/005 完成）
- `PathValidator`：已实现的白名单路径检查（FR-004 完成）
- `LlamaCppModelLoader`（`stubMode=false` 路径）：FR-007 集成测试已验证

**下游影响**：
- `InferenceViewModel`：新增 `loadModelFromUri()` 方法；`InferenceUiState` 新增 `isCopying` 字段
- `InferenceViewModel.Factory`：`jni`、`stubMode` 注入改变
- `MainActivity`：新增 `ActivityResultLauncher` 注册
- `InferenceScreen`：`onLoadModel` 回调触发时机改为弹出文件选择器（而非硬编码 `"stub"`）
- `InferenceScreenActions`：`onLoadModel` 语义从"传入路径字符串"变为"触发选择器"，可考虑改为无参 `onLoadModelClick: () -> Unit`
- `InferenceViewModelTest`：需补充 `loadModelFromUri` 的单元测试

**变更范围**：修改 ViewModel 注入 + 新增 SAF 流程 + UI 状态扩展，不新增 JNI/C++ 代码。
