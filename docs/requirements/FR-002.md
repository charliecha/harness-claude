# FR-002 接口统计

**创建日期**：2026-06-07
**状态**：Active
**Feature**：api-statistics

---

## 1. 功能需求

### FR-002-1 按端点统计调用次数

系统记录每个 API 端点被调用的次数，支持按指定时间窗口聚合查询。

**验收标准**：
- AC1：每次 API 请求完成后，对应端点的调用计数自动递增，误差为 0。
- AC2：统计查询接口支持以下时间窗口参数：`1m`、`5m`、`1h`、`24h`，至少覆盖这四种。
- AC3：查询结果中每条记录包含：端点标识（如 `/prices/single`）、时间窗口、该窗口内的调用次数。
- AC4：未被调用的端点在查询结果中不出现，或调用次数明确显示为 0，二者之一均可。

---

### FR-002-2 统计接口响应时间

系统记录每次 API 请求的响应时间，并提供统计指标供查询。

**验收标准**：
- AC1：统计指标包含：平均响应时间（mean）、P95、P99，单位为毫秒。
- AC2：响应时间统计结果可按端点和时间窗口过滤，时间窗口参数与 FR-002-1 一致。
- AC3：P95/P99 计算基于对应时间窗口内所有请求的实际耗时样本，不使用估算或固定倍数推算。
- AC4：当某端点在指定时间窗口内请求次数为 0 时，统计接口返回空或明确说明"无数据"，不返回虚假数值。

---

### FR-002-3 统计错误率

系统记录 API 请求中的错误情况，提供错误率指标。

**验收标准**：
- AC1：错误定义为 HTTP 响应状态码为 4xx 或 5xx 的请求。
- AC2：错误率 = 错误请求数 / 总请求数，精度保留到小数点后四位（如 0.0123 表示 1.23%）。
- AC3：统计结果可按端点和时间窗口查询，参数与 FR-002-1 一致。
- AC4：统计结果中分别包含：总请求数、错误请求数、错误率三个字段。

---

### FR-002-4 统计数据查询接口

提供独立的 HTTP 查询接口，允许调用方获取汇总统计数据。

**验收标准**：
- AC1：提供一个独立端点（路径不与现有 crypto-price-feed 端点冲突），返回指定端点、指定时间窗口的统计数据。
- AC2：单次查询请求的响应体中，同时包含：调用次数、平均/P95/P99 响应时间、错误率，对应于 FR-002-1、FR-002-2、FR-002-3 的全部字段。
- AC3：缺少必填查询参数时，返回明确错误信息，说明缺少哪个参数及其可选值。
- AC4：查询接口的响应本身不计入统计（即查询统计数据的请求不污染被查询端点的计数）。

## 2. 非功能需求

| 编号 | 类别 | 描述 |
|------|------|------|
| NFR-002-1 | 统计写入性能 | 每次 API 请求完成后，统计数据写入操作对原始请求的额外延迟不超过 5ms（P99）。 |
| NFR-002-2 | 统计查询响应时间 | 统计查询接口在数据量不超过 10 万条样本时，P99 响应时间不超过 500ms。 |
| NFR-002-3 | 数据保留周期 | 统计原始样本数据至少保留 7 天，聚合后的分钟/小时级摘要至少保留 30 天。 |
| NFR-002-4 | 并发写入 | 统计写入模块在 200 并发请求下，不出现数据丢失或计数错误（误差为 0）。 |
| NFR-002-5 | 存储上限 | 原始样本数据在 7 天保留期内预估存储占用不超过 1GB（基于每天 10 万次调用估算）。 |
| NFR-002-6 | 统计覆盖完整性 | 统计模块对已有 FR-001 的所有端点均需自动覆盖，无需人工逐一配置。 |

## 3. 排除范围

以下内容明确不属于本需求的交付范围：

- **实时推送/告警**：不提供基于阈值的自动告警或 Webhook 推送，错误率超标不触发通知。
- **可视化仪表盘**：不包含图表或 Web UI 展示，统计数据仅通过 API 接口交付。
- **用户维度统计**：不按调用方身份（IP、API Key 等）细分统计，本需求仅统计端点维度。
- **分布式追踪**：不实现 Trace ID 链路追踪，统计为聚合指标，不关联单次请求完整链路。
- **计费/限流**：统计数据不用于限流或按量计费逻辑，相关功能属独立需求。
- **历史数据回填**：统计功能上线前的历史调用数据不纳入统计，只统计功能启用后的请求。
