# FR-006 端侧 LLM 推理接口 — Token 生成与流式输出

**创建日期**：2026-06-09
**状态**：Active
**Feature**：fr-006-inference-api

---

## 1. 业务上下文

- **谁会用**：Android LLM 推理助手的 UI 层（ViewModel + Compose）以及集成测试。
- **解决什么问题**：FR-004/005 完成了模型加载（`ModelHandle`），但加载后的模型不能生成文本。缺少从 prompt 到 token 流的完整推理路径，导致端侧 LLM 功能无法交付给用户。
- **价值**：交付后，调用方传入 prompt 字符串即可通过 `Flow<String>` 实时接收生成的文本片段，实现流式对话体验。这是所有上层功能（对话 UI、RAG、智能助手）的基础能力。

---

## 2. 功能需求

### FR-006-1 推理上下文接口

定义 `InferenceSession` 抽象，封装 llama.cpp `llama_context*` 的生命周期，提供从 `ModelHandle` 创建会话的工厂方法。

**验收标准**：
- AC1：`InferenceSession` 实现 `Closeable`；`close()` 幂等，多次调用安全。
- AC2：通过 `InferenceSession.create(handle, params)` 可从已加载的 `ModelHandle` 创建会话；`handle` 已释放时抛出 `IllegalStateException`。
- AC3：`InferenceSession` 暴露 `contextSize: Int`（当前上下文窗口 token 数）和 `usedTokens: Int`（已使用 token 数）只读属性。

### FR-006-2 Tokenize / Detokenize

提供 prompt → token id 列表和 token id → 文本片段的转换，作为推理管道的前置和后置步骤。

**验收标准**：
- AC1：`InferenceSession.tokenize(text: String): List<Int>` 返回 token id 列表，结果非空（至少含 BOS token）。
- AC2：`InferenceSession.tokenToText(tokenId: Int): String` 返回该 token 对应的文本片段（可为空字符串）。
- AC3：`tokenize("Hello") |> map(tokenToText) |> join("")` 得到的文本与 `"Hello"` 语义等价（round-trip 验证，允许 tokenizer 规范化差异）。

### FR-006-3 流式 Token 生成

核心推理功能：接受 prompt 和采样参数，返回 `Flow<String>` 逐 token 发射文本片段，直到 EOG（End-Of-Generation）token 或达到最大 token 数。

**验收标准**：
- AC1：`InferenceSession.generate(prompt: String, params: InferenceParams): Flow<String>` 在 `Dispatchers.Default` 或指定 dispatcher 上运行；主线程调用时立即抛 `IllegalStateException`。
- AC2：Flow 收集到 EOG token 或 `params.maxNewTokens` 时自动 complete，不挂起。
- AC3：Flow 收集被取消（`job.cancel()`）时，C++ 推理循环在下一次迭代后停止，不泄漏 `llama_context`。
- AC4：`InferenceParams` 包含 `maxNewTokens: Int`（默认 128）、`temperature: Float`（默认 0.8）、`topP: Float`（默认 0.9）、`seed: Int`（默认 -1 表示随机）。
- AC5：单次生成调用后 KV cache 保持有效，同一 `InferenceSession` 可继续调用 `generate` 追加上下文（multi-turn 基础）。

### FR-006-4 ViewModel 示例集成

在 `MainActivity` 中添加 `InferenceViewModel`，演示完整加载 → 推理 → 流式显示 UI 流程，满足 FR-004-4 AC1 遗留的 viewModelScope 绑定要求（RV-004 W-004-1）。

**验收标准**：
- AC1：`InferenceViewModel` 使用 `viewModelScope.launch` 发起推理；ViewModel 销毁时通过 `viewModelScope` 取消自动停止生成。
- AC2：`MainActivity` 的 `InferenceScreen` 组合函数显示生成文本，支持"发送"按钮触发推理、实时追加 token 到 UI。
- AC3：`InferenceScreen` 在推理中显示加载指示器；推理出错时显示错误信息（非 crash）。

## 3. 非功能需求

| 编号 | 类别 | 描述 |
|------|------|------|
| NFR-006-1 | 响应时间 | 第一个 token 延迟（TTFT）在 1B Q4 模型、arm64 真机上 ≤ 2s |
| NFR-006-2 | 吞吐 | token 生成速率 ≥ 3 token/s（1B Q4，arm64 真机，无 GPU） |
| NFR-006-3 | 内存 | 推理过程中 JVM 堆增长 ≤ 20MB（KV cache 在 native 侧） |
| NFR-006-4 | 线程安全 | 同一 `InferenceSession` 不允许并发 `generate` 调用；第二次调用立即返回 `Result.failure` |
| NFR-006-5 | 可观测性 | 使用 Timber 记录 TTFT、tokens/s、total tokens、错误类型 |
| NFR-006-6 | 测试覆盖 | 单元测试覆盖率 ≥ 80%；JNI instrumented 测试验证真实 token 生成 |

## 4. 排除范围

- **多轮对话历史管理**：`generate` 不自动维护对话历史格式（如 ChatML），由上层 prompt 构建。
- **流式 HTTP/WebSocket 接口**：本期为端侧纯本地推理，无网络输出。
- **批量推理（batch size > 1）**：仅支持单序列推理，batch 优化属于性能优化 FR。
- **LoRA / adapter 热插拔**：不实现适配器加载。
- **量化感知推理后处理**：不实现 speculative decoding、beam search 等高级采样策略，仅支持 greedy + top-p + temperature。
- **模型下载 UI**：用户侧获取 GGUF 文件属于单独 FR。
- **GPU 后端（Vulkan）**：CPU 推理，与 FR-005 保持一致。
