# FR-003 API 健康检查

**创建日期**：2026-06-09
**状态**：Active
**Feature**：health-check

---

## 1. 功能需求

### FR-003-1 健康检查端点

提供 `GET /health` 端点，返回服务运行状态。

**验收标准**：
- AC1：`GET /health` 返回 HTTP 200 和 JSON body。
- AC2：响应 body 包含 `status` 字段，值为 `"ok"`。
- AC3：响应 body 包含 `version` 字段，值为当前服务版本号（字符串）。
- AC4：响应 body 包含 `timestamp` 字段，值为请求处理时的 ISO 8601 UTC 时间戳。
- AC5：`/health` 端点的访问不计入统计（与 `/stats` 同等豁免）。

### FR-003-2 依赖状态探测（可选）

健康检查端点可选择性返回依赖组件的状态。

**验收标准**：
- AC1：响应 body 包含 `checks` 字段，值为对象，每个依赖一个子字段。
- AC2：当前版本的唯一检测项为 `memory`（内存压力检测），报告 `"healthy"` 或 `"degraded"`。
- AC3：内存检测使用 `psutil` 标准判断（低于 90% 使用率视为 healthy）。
- AC4：单依赖检测失败不影响整体 200 响应，仅在 `checks` 中标记状态。

## 2. 非功能需求

| 编号 | 类别 | 描述 |
|------|------|------|
| NFR-003-1 | 响应时间 | `/health` 端点 P99 响应时间不超过 50ms（不含依赖探测降级时的额外耗时）。 |
| NFR-003-2 | 豁免 | `/health` 不被限流、不计入统计（编辑 _EXEMPT_PREFIXES 或 StatsMiddleware 跳过路径）。 |
| NFR-003-3 | 幂等 | `GET /health` 无副作用。 |

---

## 3. 排除范围

以下内容明确不属于本需求的交付范围：

- **健康检查鉴权**：端点对内网开放，不定义认证机制。
- **数据库/上游依赖探测**：当前不检测 CoinGecko 或其他外部服务可达性。
- **主动告警**：不提供阈值触发通知（如内存超 90% 发告警）。
- **启动就绪/存活分离**：不区分 liveness 和 readiness probe。
- **自定义健康阈值**：不提供可配置的健康判定参数。
